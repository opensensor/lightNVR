# Мобильный Live View и персональное избранное — журнал итерации

Дата начала: 02.10.2026. Исходный форк: https://github.com/zirocool93/NVR.
Базовый commit: 03767df2d6cbebfa388be123fa5d305a33698674 (0.42.9).
Рабочая ветка: codex/mobile-live-favorites.

## Область работ
Мобильный интерфейс только Live View, персональный server-side ui_mode auto/mobile/desktop и персональное избранное по стабильному UUID камеры. Существующая авторизация, роли, проигрыватели, recorder, go2rtc и конфигурация потоков сохраняются. Публикация и обновление действующего сервера не входят в эту итерацию.

## Процесс
Подготовлена отдельная рабочая копия актуального пользовательского форка. Запущены три независимых read-only исследования на gpt-6-luna: общая архитектура, frontend и backend. До завершения всех исследований прикладной код не изменяется. После согласования API работа будет разделена между frontend и backend агентами, затем отдельный агент проверит интеграцию; основной агент выполнит итоговое ревью.

## Состояние
Исследование выполняется. Точный API, миграция и результаты проверок будут внесены после анализа и реализации.

## Зафиксированный архитектурный план и контракт
Исследования трёх независимых read-only агентов завершены. UUID камеры подтверждён миграциями 0048/0056; персональные workspace preferences и AUTHZ_LIVE_VIEW дают готовые образцы хранения и проверки доступа.

- GET /api/ui/preferences: {ui_mode, configurable}; PUT принимает только {ui_mode}, допустимы auto/mobile/desktop, возвращает тот же объект.
- GET /api/ui/favorites: {favorites:[{camera_uuid,created_at}],configurable} с фильтрацией по действующей авторизации камеры.
- POST /api/ui/favorites: только {camera_uuid}; идемпотентный ответ 200 {camera_uuid,created_at}.
- DELETE /api/ui/favorites/:camera_uuid: идемпотентный ответ 200 {success:true}, удаляет только запись текущего пользователя.
- Пользователь берётся из существующей авторизации. Передача user_id/неизвестных полей отклоняется. Отсутствие авторизации — 401. Для demo/scoped token/отсутствия реального пользователя чтение только defaults/empty с configurable=false, изменения — 403.
- Отсутствующая/недоступная камера при добавлении — 404; удаление собственного избранного допускается после потери доступа.

Хранение: numbered migration 0088 с расширяемой user_preferences и user_favorites; FK CASCADE к users и streams(camera_uuid). Значение ui_mode по умолчанию auto без обязательного backfill. Сортировка избранного created_at, camera_uuid.

Frontend: тонкий выбор MobileLiveView либо прежней desktop ветки; PlaybackTransportCell и существующие transport cells переиспользуются. Мобильные соединения ограничены небольшим числом карточек/видимостью, принудительный режим имеет приоритет над media detection. Временный override доступен только development-сборке. Административное редактирование чужой настройки отложено как необязательное расширение, чтобы не увеличивать поверхность user management API.

Запущены два implementation агента gpt-6-luna с непересекающимися зонами владения: web и backend/DB/tests. Итоговая сборка, интеграционные проверки и ревью ещё впереди.

## Подготовка среды проверок
Node.js 24.20.0 доступен локально. Docker daemon первоначально не работал; Docker Desktop запущен скрыто для локальных проверок. В WSL Ubuntu 24.04 пока отсутствуют gcc/cmake, запросы установки зависимостей не прошли из-за недоступности сети. Сборка действующего сервера не используется; подготовка локальной среды поручена отдельному gpt-6-luna агенту без изменения прикладного кода и сетевых настроек. Вложенная рекурсивная загрузка TensorFlow остановлена после загрузки основного форка, go2rtc и LiteRT: для проверки данной итерации детектор не требуется.

## Ревью и промежуточные проверки
Основной агент прочитал изменения DB/API, регистрацию маршрутов, миграцию, frontend router, auth cache scope, mobile card lifecycle и CSS. Через Luna исправлены: чтение desktop в буфер 8 байт; порядок Preact hooks; явный приоритет выбранного режима и ожидание загрузки настроек до первого player mount; фильтрация выключенных потоков; ограничение четырьмя карточками и IntersectionObserver; clamp страницы после удаления избранного; корректные empty states и числовая сортировка created_at; fullscreen lifecycle; отключение звёзд во время запроса; использование hsl() для цветовых переменных проекта.

Frontend production build прошёл. Полный Jest suite: 310/310 при TZ=America/New_York, которое ожидают существующие DST fixtures; исходные пять ошибок при UTC/МСК не вызваны изменениями этой итерации. Generator миграций --check и его четыре unit tests прошли; backend агент дополнительно проверил SQL миграции и каскадное удаление на SQLite. Отдельный integration-tester gpt-6-luna выполняет браузерные и backend проверки.

Локальная среда GCC/CMake установлена в WSL через временный proxy и проверенные пакеты; persistent настройки сети не менялись. Требуемый FFmpeg 7+ готовится отдельной библиотекой для тестовой сборки, системный FFmpeg 6 не заменяется. Подробности среды: build-environment.md.

## Интеграционные исправления
Отдельный браузерный тест с включённым WebRTC подтвердил нулевую высоту области видео при explicit mobile на desktop viewport 1440×900. Luna frontend worker добавил стабильное соотношение 16:9 и минимальную высоту независимо от viewport, с отдельными правилами native/pseudo fullscreen. Затем тест выявил попытку Date.parse() для created_at: backend контракт использует целые Unix seconds. Сортировка исправлена числовым сравнением, а тестовые fixtures приведены к корректным UUID и числовому времени. Unit case проверяет порядок времени, противоположный лексикографическому порядку UUID. Целевые frontend unit tests: 4/4, production build после исправлений прошёл.

Проверки распределены без пересечения файлов: integration-tester владеет интеграционными тестами и браузерной проверкой, backend_explorer запускает локальный CMake/build/C suite в отдельном каталоге /tmp/nvr-backend-verification и ведёт отдельный backend-build-validation.md. Production code на этом этапе меняется только frontend worker по конкретным найденным дефектам.

## Подтверждённые браузерные результаты
Chromium: viewport телефона 390×844, landscape 844×390, desktop 1440×900 и 1440×1080. При 80 камерах mobile монтирует только видимые проигрыватели в странице из четырёх карточек: измерено 3 video elements, максимум 3 одновременных RTCPeerConnection и 3 начальных WebRTC-запроса. Explicit mobile на ширине 1440: высота player/video 412.9px, карточки 466.9px. Горизонтальное переполнение отсутствует. Fullscreen cleanup после смены фильтра/unmount подтверждён.

Проверены add/remove/reload persistence в mocked API harness, числовая сортировка timestamps, clamp после удаления с последней страницы, скрытие отсутствующей в authorized stream list избранной камеры и ошибка записи без ложного изменения состояния. Desktop отображает прежнюю сетку с 36 video cells; toolbar/grid/footer доступны в обоих desktop viewport. Контраст активной вкладки: 6.03:1 в светлой теме, 7.03:1 в тёмной. Основной агент просмотрел итоговые screenshots: outputs/nvr-mobile/02-explicit-mobile-desktop-viewport.png, 03-desktop-auto-1440x900.png, 06-theme-dark.png.

Эти проверки используют настоящий frontend и существующие player components, но заглушки HTTP API/ответа WebRTC; декодирование реального видеопотока ими не подтверждается. Настоящая backend-проверка входа, миграции и персональных данных выполняется отдельно после C-сборки.

## Дополнительная зависимость backend
Первая C-сборка обнаружила несовместимость установленного mbedTLS 2.28 со старым upstream db_api_tokens.c (API sha256 void против ожидаемого int). Код авторизации не менялся. Подготовлен официальный mbedTLS 3.6.7 shared в отдельном тестовом prefix /opt/lightnvr-test-deps, повторная сборка выполняется с соответствующими headers/libs. Детали и результаты в backend-build-validation.md.

## Backend-сборка и исходный сбой теста
Штатная сборка CMake (SOD/LiteRT отключены только в тестовой конфигурации) прошла с FFmpeg 7.1, llhttp 9.2.1 и mbedTLS 3.6.7. Общий CTest: 144/145, новый test_api_handlers_ui_preferences проходит. Единственный сбой test_url_utils связан с регистром percent-escape %3A/%3a; исходники реализации и теста совпадают с базовым HEAD, изолированный повтор подтверждает исходную ошибку. Несвязанные исходники/тесты URL не изменялись. Полные команды и свидетельства: backend-build-validation.md.

## Уточнение жизненного цикла WebRTC
Стресс-проверка смены мобильных страниц обнаружила настоящую утечку в существующем WebRTCVideoCell: асинхронная загрузка config/ICE могла завершиться после cleanup, создать поздний RTCPeerConnection и выйти по отменённому connection gate без его закрытия. Основной агент разрешил минимальное изменение только lifecycle guards существующего frontend WebRTC-компонента: проверки AbortSignal после await, abort-aware ICE fetch, закрытие локального PC при отмене, очистка ref только при совпадении с этой попыткой. Сигнализация, транспортная логика, backend, go2rtc и recorder не менялись; второй видеостек не создавался. Это точечное исправление необходимо для безопасного lazy unmount/mobile pagination, а не переписывание проигрывателей. Отдельному тестировщику поручены browser regression с задержкой ICE response и проверкой отсутствия post-unmount PC, а также стресс-прогон всех 20 страниц 80 камер; результаты получены и приведены в итоговом разделе ниже.

Автоопределение уточнено: ширина <=760px либо coarse pointer и ширина <=1024px. Это сохраняет desktop при ширине 1440px и поддерживает широкие landscape окна телефона. Development override не влияет на сохранённые предпочтения.
