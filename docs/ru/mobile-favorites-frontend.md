# Мобильный режим и избранные камеры

## Поведение интерфейса

На странице Live View доступен переключатель режима: «Автоматически», «Мобильный интерфейс» и «Компьютерный интерфейс». Выбор хранится сервером в настройках текущего пользователя. Автоматический режим выбирает мобильный интерфейс при ширине окна до 760 px либо при coarse pointer и ширине до 1024 px. Режим обновляется при изменении окна. Пока серверные настройки загружаются, плееры не монтируются; если запрос настроек недоступен, интерфейс использует временный автоматический выбор и показывает сообщение.

Мобильное представление показывает поиск и вкладки «Все камеры» / «Избранное». Камеры загружаются тем же кратким Live API списком, что и существующие live-поверхности. Карточки идентифицируются по `camera_uuid`; страницы содержат не более четырёх карточек, а `PlaybackTransportCell` запускается только для пересёкших область просмотра карточек. Область плеера имеет пропорции 16:9 и минимальную высоту на любой ширине окна, поэтому высота не зависит от мобильного media query. Режим полного экрана использует размеры viewport без ограничения 16:9. Встроенные WebRTC/HLS/MSE-плееры и правила доступности транспортов остаются существующими.

## API контракт

- `GET /api/ui/preferences` возвращает `{ui_mode, configurable}`.
- `PUT /api/ui/preferences` отправляет только `{ui_mode}`.
- `GET /api/ui/favorites` возвращает `{favorites, configurable}`.
- `POST /api/ui/favorites` отправляет только `{camera_uuid}`; успешный ответ добавляется в query-кэш без перезагрузки.
- `DELETE /api/ui/favorites/:camera_uuid` удаляет запись и обновляет query-кэш без перезагрузки.

Query keys включают идентификатор пользователя из проверенной сессии. Для demo и сессий без user ID применяется отдельный scoped ключ. Любые действия с избранным выполняются через сервер; localStorage не используется.
Краткий список камер и избранное повторно запрашиваются каждые 30 секунд, чтобы изменения доступности и прав со стороны сервера появлялись в интерфейсе без перезагрузки.

## Жизненный цикл WebRTC на мобильной странице

При быстрой смене страницы WebRTC карточка может размонтироваться, пока ещё получает URL go2rtc, клиентские таймауты или ICE-серверы. Ранее cleanup отменял signal и закрывал только уже присвоенный `peerConnectionRef`; продолжившаяся после ожиданий инициализация могла создать новое RTCPeerConnection после cleanup, а abort запроса предложения завершался без закрытия этого позднего соединения. Инициализация теперь выходит после отмены на границах этих ожиданий, ICE fetch использует cell-scoped signal, а abort-обработчик закрывает локальное соединение и очищает ref только если он всё ещё указывает на ту же peer connection.

## Разработка и ограничения

В режиме разработки параметр `?ui_mode=mobile` или `?ui_mode=desktop` временно переопределяет визуальный режим без записи в API.

В этой реализации переключатель показан на главном Live View; правка режима администратором и отдельная адаптация `hls.html` не входят в мобильный интерфейс. Если server preferences недоступны, серверное значение восстановится при следующей загрузке, а интерфейс использует auto только для текущего просмотра.
