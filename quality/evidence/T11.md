### Order of checks (from C)

- `/full`: path decode (400 "Invalid request path"), then `get_stream_by_name` (404 "Stream not
  found", which runs **before authentication**), then config read (500), then
  `httpd_authorize_stream_action_with_context` (401 "Unauthorized", 404 "Camera not found",
  500 "Authorization policy evaluation failed", 403 "Forbidden"), then the variant chosen by
  `stream_user_can_modify`.
- PUT: same order up to `check_stream_write_access` (camera.configure), then the body parse (400
  "Invalid JSON in request body"), then per-field validation in handler order. There are no
  partial writes on a 4xx.
- summary: 401, then page/page_size, sort_by, sort_order, surface, availability (400 messages
  recorded on each parameter), then per-row authorization.

## Redaction modelling

- **Separate schemas.** The summary rows (`StreamSummaryAdmin`, `StreamSummaryLive`,
  `StreamSummaryLpr`) are separate from the detail object. The detail object has two variants:
  `StreamDetailConfigurable` (admin edit model) and `StreamDetailLiveOnly` (viewer). Request
  bodies are separate too: `StreamUpdateRequest` and `StreamPrivacyModeRequest`. Variant
  selection is annotated with `x-lightnvr-response-variant-by-query` (surface) and
  `x-lightnvr-response-variant-by-field` (`can_control_privacy`).
- **Viewer model.** The credential-bearing keys are `url`, `onvif_username`, `onvif_password`,
  `admin_url`, `go2rtc_source_override`, `sub_stream_url`, `detection_url` and `publish_url`.
  None of them is required. When one is present, the onvif and admin keys must equal `""`
  (`EmptyString` const). `url` must be `ViewerSafeUrl`: it may not contain userinfo, and it may
  not contain a non-empty query parameter whose name contains pass, pwd, token, secret or apikey.
  `can_control_privacy` is const false. As a result, any leaked value fails validation. There is
  one known-invalid fixture per sensitive key.
- **Admin model.** All sensitive keys are required, and `can_control_privacy` is const true.
  When separate credentials are in use (isOnvif, or non-empty onvif_* fields), `url` must not
  contain userinfo. This mirrors `get_stream_api_credentials`.
- **Summary rows.** `SummaryForbiddenSensitiveKeys` rejects `url`, `onvif_*`,
  `sub_stream_url`, `detection_url`, `publish_url`, `go2rtc_source_override` and
  `detection_api_url` whatever their value. `admin_url` must be `""` when
  `can_configure:false`. Live rows must not contain `admin_url`. LPR rows are a closed object
  with only identity fields.
- **Not hidden, by design (current behavior):** viewers can still read `has_sub_stream`, the
  credential-free `url` host/path, `motion_trigger_source`, `detection_model` (which may be a
  filesystem path), `onvif_profile` and `onvif_port`.

## Semantics confirmed from C

- **Retention is tri-state.** `-1` inherits the live global value, `0` means unlimited and also
  skips tier expiry, and `1..365` is a day override. Sources: `include/core/config.h`,
  `src/storage/storage_manager.c:556-563,1579-1584`, and the PUT range check at
  `api_handlers_streams_modify.c:1512-1544`. `detection_retention_days=-1` inherits the
  *global* value, not the stream's `retention_days`. The PUT check uses `valueint`, so a
  fractional value is truncated before the range test.
- **Schedules** are 168 booleans indexed `tm_wday*24+tm_hour` in server local time, with
  Sunday as 0 (`src/video/stream_manager.c:103-133`).
- **`detection_threshold`** is an integer percent on the wire: `(int)(float*100.0f)` on read
  and `value/100.0` on write.
- **Numeric limits enforced by C:** retention fields (-1..365), summary page (1..1000000),
  page_size (1..100), and the eptz document ranges. No other numeric field is range-checked.
  Those fields are declared as int32 and carry `x-lightnvr-intended-range` annotations.
- **String byte limits** come from the `stream_config_t` buffers. Truncation is silent except
  for detection_url and publish_url (413) and eptz_config (400).
- **Nullability.** The server never emits null. On PUT, null clears exactly seven fields: tags,
  admin_url, motion_trigger_source, go2rtc_source_override, sub_stream_url, detection_url and
  publish_url. A null on any other key is ignored.
- **Encoded names.** The route matches the encoded segment. The decode then maps `%XX` and maps
  a literal `+` to a space. The encoded segment must be under 256 bytes. Dot segments are
  rejected by the parser. New names must match `^[A-Za-z0-9_-][A-Za-z0-9._-]*$`, but legacy
  names can contain anything. Cases are in `path-encoding.cases.json`.
- **Response headers.** Every JSON response carries `Cache-Control: no-cache, no-store,
  must-revalidate`, `Pragma`, `Expires` and CORS headers (`http_response_set_json`).
- **Error envelope.** `{"error": "<message>"}` from `http_response_set_json_error`.

## Notes for downstream tasks

- **T12 (dialect and refs).** The root uses `openapi: 3.1.0` with `jsonSchemaDialect` set to the
  OAS 3.1 base dialect. Paths are Path Item `$ref`s into `contracts/streams.yaml`, with `{`/`}`
  percent-encoded in the fragment (`~1%7Bname%7D`). Schemas use relative refs
  (`./common.yaml#/...`) resolved against each fragment's own location. The fragments are not
  standalone OpenAPI documents; each has only top-level `paths` and/or `components`. Bundle with
  a resolver that supports Path Item refs (for example redocly or
  @apidevtools/json-schema-ref-parser) before running openapi-typescript.
- **T12 (keywords that need care).**
  - `const`, `if`/`then`, `not`, `dependentRequired` and `contentMediaType`/`contentSchema` are
    used. `contentSchema` must be enforced explicitly for `eptz_config`.
  - Type arrays are used for nullable request fields (`[string, 'null']`).
  - `oneOf` without a `discriminator`: OpenAPI discriminators cannot map boolean const values.
  - `anyOf` covers the surface-dependent list response.
  - Patterns are ECMA-262 compatible and verified with the `u` flag.
  - `maxLength` counts code points, while C limits are bytes (`x-lightnvr-max-bytes`).
  - The `x-lightnvr-response-variant-by-query` and `-by-field` annotations tell the generator
    which concrete schema to validate per surface or variant. Generate standalone validators
    for the variant schemas, not only for the anyOf/oneOf unions.
  - Expect openapi-typescript to emit `never`-ish types for `not: {required: [...]}`. That is
    acceptable for sensitive-key exclusion.
- **T12 (policy).** Response objects are open except for the LPR rows and the explicit
  sensitive-key exclusions. Request bodies are closed.
- **T18.** Use `expected_server_response` on the request fixtures, not `expect`. The
  invalid-request fixtures describe bodies the contract forbids, and several of them are
  accepted with 202 by the current C code (F-T11-05/06/07/14, D-01). Expect
  `url-query-secret` to reproduce F-T11-03.
- **T19.** Encode names with `encodeURIComponent` (never a raw `+`). Treat 202 as "accepted",
  not "persisted". Select the detail variant by `can_control_privacy`.
