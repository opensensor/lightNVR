# T31.2 — Final stream-state disposal and unlocked stop callbacks

A private final-disposal helper destroys both initialized state mutexes and frees
one state. Normal removal and global shutdown share it; partial-construction
failure cleanup remains separate because only the first mutex is initialized.

Global shutdown marks a registry teardown guard while holding `states_mutex`,
releases the registry lock around the existing synchronous stop call, and
reacquires it before final disposal. The entry stays discoverable for HLS stop
callbacks. Create/remove/recursive-shutdown requests are rejected while teardown
owns the registry, including a test with a genuinely spare admission slot.

The scope preserves stop ordering, `wait_for_completion=false` during final
shutdown, existing active/starting selection, reference refusal, public APIs and
persistent state. The existing application teardown precondition remains:
request/stream producers must already be quiescent before final disposal. This
change does not fix arbitrary borrowed-pointer lifetime races, all stop failures,
or general state-transition synchronization.
