# T7.165 — dialog click boundaries

Resolved the four assigned click/key warnings in RoleManagerModal and
TotpSetupModal without turning either surface into a button or adding synthetic
Enter/Space handlers. Each backdrop is explicitly presentational and owns one
click boundary: stop propagation, then dismiss only when target===currentTarget.
RoleManager's existing saving guard is retained. Inner content no longer needs
its own click-stop handler because bubbled content clicks fail the target test.
Native Close buttons and all form/action callbacks remain unchanged.

The [W3C modal dialog pattern](https://www.w3.org/WAI/ARIA/apg/patterns/dialog-modal/)
distinguishes dialog content/controls from its dimmed exterior and recommends a
visible close button. Here the backdrop is a visual pointer-dismissal boundary,
not a second action control. The existing native Close button supplies keyboard
dismissal; generic container Enter/Space would risk activating nested controls
or forms twice. No strings, CSS classes, dependencies, suppressions or lint rules
were changed. Callers in UsersView pass the existing no-argument closeModal.

Scope is intentionally bounded. RoleManager's existing dialog role/name and
Escape behavior are preserved. TOTP's broader dialog semantics, Escape support,
focus trapping and focus return are **not solved** by this task. Its existing
verification autofocus remains unchanged, including its separately tracked lint
warning. This is not a full modal accessibility/conformance claim.

The actual browser interaction control already passed before implementation
(`browser-before-corrected.log`: four Node failures, five passes including the

pointer behavior; the fix consolidates boundaries while retaining that behavior.
No invented pre-existing keyboard defect is claimed.

The Node tests inspect actual vnodes/callbacks. The Chromium supplement bundles
and mounts both actual components with real Preact hooks, AsyncButton and nested
ConfirmDialog. Translation/API/QR services use explicit synthetic fixtures; no
backend requests or secrets are used. It loads the actual built Users stylesheet
and checks focus-visible styling, rather than supplying fake focus CSS.

Interaction assertions cover:

- One direct backdrop dismissal; nested input/Space/action interaction does not
  close the parent or dispatch the backdrop callback.
- RoleManager save submits once; disabled Close, Escape and backdrop dismissal
  stay blocked while saving. The test waits for the actual key-listener effect
  update through an instrumented registration counter, without arbitrary sleeps.
- Nested ConfirmDialog gets initial Cancel focus; Escape closes only the nested
  dialog, preserving its parent. RoleManager's native Close still works.
- Both dialogs' native Close activates once for Enter and once for Space.
- TOTP setup activates once via Space, verification input retains autofocus,
  and Enter verification produces one request/success callback without dismissal.

No generic key handlers, extra Tab stops or swallowed Escape events are added.
The optional browser suite uses installed root Playwright/web esbuild only.
