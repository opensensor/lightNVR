# T13 — Isolated native and integration runners

## Result and limits

Runner implementation is complete with failing negative checks, a passing
ASan/UBSan native test, and a passing real-server API smoke. The full API suite
is **not green**: it exposed two existing assertion mismatches and a separate

## Commands and interfaces

```sh
python3 scripts/quality/run-native.py --task T13 --regex '^test_system_health_proc$'
python3 scripts/quality/run-native.py --task T31.3 --sanitizer asan-ubsan --regex '^test_stream_state.*$'
node scripts/quality/run-integration.mjs --task T13 --project api --grep @api
```

Native options: `--profile lean|integration|full`, `--sanitizer none|asan-ubsan`,
`--jobs N`, `--build-only`. Default is lean with ASan/UBSan. Lean disables
SOD/LiteRT/go2rtc/MQTT; integration enables go2rtc; full enables all four (dynamic
SOD). These profiles describe compiled features, not qualification of unrun
features. `--build-only` explicitly builds the server without claiming test
execution. Debug uses the project's ASan/UBSan flags; Release selects no
sanitizer. Tests/builds live under `build/eng-native/<task>/<profile>-<sanitizer>`
and per-invocation reports under `build/eng-artifacts/<task>/native-<unique>`.

Integration defaults to API with go2rtc. It builds a current Release/integration
server through the native runner unless `--binary <explicit-path>` is supplied.
`--without-go2rtc` is an explicit runtime fixture choice; a passing lean smoke
does not qualify media. The wrapper records the selected binary SHA-256 and
selected test count. Retries are zero. JSON, list logs, traces/screenshots and
reports are placed under a unique task artifact directory. No selected tests or
skipped-only execution can report success.

Direct `npx playwright test`/the old `npm test` invocation is intentionally
refused by global setup until an owned run context is supplied. T15 must wire
existing workflows/contributor commands to the runner. This interim integration
requirement is not being hidden as a passing CI state. `--list` still works
without starting a server.

## Ownership and isolation

- Native and integration wrappers share the same exclusive directory lease at
  `build/eng-artifacts/.runtime-lock`. Existing fixed ports and legacy screenshot
  paths therefore serialize; concurrent isolated execution is **not claimed**.
  A lock is never stolen/deleted based only on age or a PID. An interrupted
  process can leave a stale lock, which requires checking its retained runtime
  records and confirming no run is active before operator recovery.
- The wrapper rejects external/credential-bearing LIGHTNVR_URL and GO2RTC_URL
  before building or running. HTTP control is loopback only. Both IPv4 and IPv6
  reserved ports are checked before startup; an existing server is never adopted.
- Each integration run creates a unique `/tmp/lightnvr-eng-<task>-<suffix>`
  directory and generates all config/DB/storage/model/PID paths inside it.
  Environment overrides are cleared and rewritten. Config hashes, token and
  canonical paths are validated before startup. Later normal server config saves
  do not revoke process ownership.
- Setup does not recursively delete existing directories. Teardown has no raw
  PID-file fallback and retains disposable data for diagnosis.
- The process record binds PID to executable, exact `-c` configuration path,
  kernel start ticks and run token. Signals use Linux pidfds with a second
  identity check (including full argv), closing the PID-reuse check/signal race.
  Python 3 with pidfd support and Linux `/proc` are required; there is no unsafe
  numeric-PID fallback.
- Descendants are recorded before tests and again before shutdown. If graceful
  shutdown leaves them behind, cleanup signals only captured executable/argv/
  start-time identities via pidfds, retaining all identities and forced-cleanup
  results. A forced parent kill or child cleanup remains a failed run.
- The graceful server deadline is 60 seconds, recorded independently from fallback
  kill. This is a harness teardown deadline, not a newly approved product resource
  budget.

Two bounded fixture/config prerequisites extend the original shared-file scope:
`go2rtc.api.spec.ts` writes its capture into the owned runtime directory instead
of `/tmp/lightnvr-test`; `lightnvr.api.spec.ts` uses the owned RTSP port (18554 by
this serial profile) instead of accidentally contacting port 8554. No assertion
was weakened. Other real RTSP fixtures already use 18554; private-address strings
in UI mock responses are not live camera credentials.

## Native dependencies and test registration

The native runner clears inherited compiler/include/linker/pkgconfig overrides,
uses system multiarch pkgconfig paths, and passes the selected system include
paths ahead of stale `/usr/local` FFmpeg headers. It compiles and runs a probe
comparing header/runtime major versions for avcodec, avformat, avutil, swscale,
swresample and avfilter before configuring CMake. Any mismatch is a failure;
this does not modify the host. Probe source/output, configure/build logs and
CTest selection/JUnit reports are retained.

`tests/unit/CMakeLists.txt` now includes sorted
`tests/unit/cmake/eng/*.cmake` fragments (CONFIGURE_DEPENDS where supported).
Future T27–T31 tasks can register independent tests without editing the shared
CMake list.

`build/eng-artifacts/T13-smoke/integration-105ce37b-a48e-4da3-aa28-41eab776cab2/`.
The server log ends inside stream-state shutdown after
`Attempting to stop HLS stream: test_pattern`. The coordinator traced the lock

then stream_stop_hls / stop_hls_stream re-enters get_stream_state_by_name.

That early smoke used the first descendant-reporting implementation: it retained
five live child identities after the forced server kill. Those **exact observed
PIDs/start times** were then stopped through pidfds; `owned-child-cleanup.json`
records go2rtc and four FFmpeg children, all exited. The final helper automates
that verified descendant cleanup while still reporting failure; its controlled
hang unittest proves this behavior. No process-name/global kill was used.
