# T7.174 — explicit names for timeline and user controls

All 27 assigned control-has-associated-label findings are resolved in the six
owned components. Names reuse existing translations and visible text; no new
locale keys, dependencies, suppressions, shared-test edits, baseline changes or
policy exceptions were added. Most form fields already had native implicit or
explicit labels; this task supplies explicit per-control names recognized by the
scanner without claiming all fields were previously unnamed in browsers.

- TimelineControls' two zoom icon buttons use their existing localized tooltip
  labels as aria-label values. Their titles, disabled rules, callbacks, native
  button semantics and keyboard-navigation preservation attributes remain.
- TimelinePlayer's native video uses the existing timeline.timelinePlayback
  translation. Its detection checkbox uses the same translated text and optional
  count as the visible label. The rendered detection layer is a named image
  wrapper containing the original drawing canvas as decorative pixels. Absolute
  bounds, z-index, pointer transparency and canvasRef remain; no extra image is
  exposed when the layer is absent or suppressed for EPTZ. Video/native-controls
  and detection-toggle callbacks are unchanged.
- AddUser/EditUser: six reported fields each use their existing visible localized
  field names: username, password, email, active, password-change lock and allowed
  login IP ranges. Edit keeps its distinct password-help label. The existing
  visible CIDR abbreviation remains; the accessible name uses the localized main
  field label. Existing IDs, htmlFor associations, form callbacks and guards are
  unchanged; no new cross-instance ID references are introduced.
- ApiKey: token description uses its existing label; action checkboxes combine
  the visible action identifier, optional localized destructive marker and
  description; show-inactive uses its existing localized count label; secret
  confirmation combines its existing confirmation/help text. These controls keep
  their original state and callbacks.
- AuditHistory: the six reported retention/action/date/request/target inputs use
  their existing localized visible names. Retention validation, filter/query
  updates, save/export guards and callbacks are unchanged.

## Tests first and native accessibility evidence

Tests were written directly before implementation; no independent test-writer
slot was available. The initial Node run failed seven control-name assertions
while the pre-existing EPTZ-disabled-layer guard passed (`jest-red.log`). The
corrected browser RED run failed Add/Edit scoped field-name resolution and zoom
names after removing titles, with existing API/Audit interaction controls passing
(`browser-red-corrected.log`). Initial browser setup used an originless document,
which prevented the actual EPTZ child from reading localStorage; that fixture
failure is retained separately in `browser-red.log` and is not product evidence.

The final focused suite has eight passing Node cases and four actual Chromium
cases. The default run selects the Node cases and leaves the browser supplement
unselected. Coverage includes:

- Every reported field's explicit localized name and original input/toggle
  callback, API secret/action/inactive state updates and zoom range callbacks.
- Simultaneously mounted Add/Edit forms: each scoped name resolves to its own
  control, edits/toggles update only that instance and no modal dismisses.
  This verifies naming/callback independence without changing existing DOM IDs.
- API description/action/inactive controls and one real component token-create
  flow against synthetic service responses, with exact payload/call count;
  confirmation keeps Done disabled until the named checkbox is activated.
- All six Audit input names, actual retention update and applied filter query
  values, without invoking a live API.
- Zoom names survive title removal, native Enter/Space cause exactly one range
  update each, and the zoom-out limit remains disabled.
- Chromium's native Video accessibility node exposes the playback name after
  loading the existing 18 KB repository fixture
  `tests/integration/fixtures/recording.mp4`. Playwright's ARIA-role serializer
  omits this native media role, so the test queries Chromium's actual AX tree
  through CDP. An empty/unplayable video correctly exposes Chromium's media-error
  text instead; that exploratory result is retained in browser-green-final.log.
- The detection image appears only when enabled, its canvas and wrapper match
  the video-container bounds, pointer-events remains none, its pixels are not
  independently announced, and it disappears when unchecked. Node coverage also
  verifies EPTZ disables the toggle and suppresses the image even if overlay state
  was true.

The browser uses actual Preact/components and built Users/Timeline styles.
External services and the timeline state owner are fixtures; the tiny existing
video is served by a local Playwright route. Tests assert zero uncaught page
errors. This is an accessible-name check for playable media, not a full playback,
codec, system-restart or backend-media acceptance run. The earlier T7.163 and
T7.164 actual-browser suites run alongside it to preserve media interactions,
selection, drag behavior, modal saving/reveal/export guards and native actions.

Fixture corrections are preserved in logs: Preact/compat normalizes the Node
input callback prop to oninput; the initial generic state-update counter included
an unrelated player initialization update, so the final assertion counts the
specific zoom range updates while retaining the exact two-dispatch requirement.
The first aria-label draft copied the existing literal `(CIDR)` suffix and the
translation rule rejected it. The final attribute uses the existing translated
main label; no lint exception or new string was introduced.
