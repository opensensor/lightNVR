## Workload and measurement method

`quality/runtime-budgets.json` defines a repeatable proposed calibration protocol:
synthetic H.264 baseline 1280×720, 15 fps, 1 Mbit/s, 30-frame GOP, no B frames;
video-only and AAC mono 48 kHz/64 kbit/s variants; zero/one/four streams; 60-second
segments; idle, recording, and recording-plus-browser phases. Generate the
source off-target and archive exact encoder version, command, media hash and
ffprobe output before taking a baseline. This is an experimental protocol,
not a claim that the fixture or the physical runs already exist.

Physical calibration calls for five independent runs with one-second resource
samples, 60/120-second warmups and 300/600-second measurement phases. These
numbers define the experiment; they are not fabricated performance limits.
Future T27–T30 runners must implement the protocol and preserve its metadata.

NVR PID/child CPU, RSS, file descriptors and threads are separate from browser
process/heap and interaction measurements. Recording continuity is derived from
actual playable segments and timestamps. Cold browser runs use fresh profiles
and cleared/disabled HTTP cache; warm runs reuse cache. “Cold NVR” means a new
process/database, not a claim to have flushed host page caches. No global cache
drop or production data is used. Metrics unavailable on a browser stay
unavailable, never zero. Derive tolerances from repeated physical measurements
and product recovery requirements before any numeric runtime gate is enabled.

## Host-only idle reference

The coordinator granted an exclusive native/server/media measurement lease.
The experiment ran the archived release binary three times on the existing
AMD Ryzen 9 7950X, 32 logical CPUs, 128,614,452 KiB RAM, Ubuntu host with kernel
7.0.0-38-generic. This is not a constrained device and is not the shipped Debian
container. The archived binary is 10,362,224 bytes, SHA-256
`a56ce959b256f08dd04fd72e0ad8054669ad300464894d99995efca2928a61d1`.

Method: fresh process and disposable database per run, loopback ephemeral HTTP
port, archived default web assets, no browser or streams, go2rtc and MQTT
disabled at runtime, health collector enabled, hardware provider disabled.
Clear all `LIGHTNVR_*` environment overrides; set `LD_LIBRARY_PATH` to the
archive's `bin/` so the archived SOD library is used. Start with
`<archive>/bin/lightnvr -c <run-directory>/lightnvr.ini` and wait for HTTP
readiness; warm up 20 seconds then take 60 one-second `/proc/<owned-pid>`
samples. CPU is delta user+system ticks / CLK_TCK / monotonic interval × 100,
where one full core is 100%. Record RSS/high-water RSS, FD count and threads.
Terminate only the subprocess created by that run; record graceful shutdown
separately from a 20-second fallback kill. No global process-name kills or
shared PID/storage directories are used.

The exact collector and synthetic configurations are retained under ignored
`build/eng-artifacts/T5/measure-idle.py` and `idle-{1,2,3}/lightnvr.ini`.
`python3 build/eng-artifacts/T5/measure-idle.py` reproduces the experiment in
an empty T5 artifact directory; it intentionally refuses to overwrite existing
run directories. Preserve/move the existing T5 directory before a repeat, then
restore the collector. The raw `idle-host.json` and each run's stdout/logs are
retained there. These artifacts are local evidence, not installed product code.

The host run is deliberately a shorter reference than the physical calibration
protocol. It cannot support recording/browser/recovery budgets and does not
qualify runtime-disabled features simply because they are compiled in.
