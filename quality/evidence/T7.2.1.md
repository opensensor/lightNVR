# T7.2.1 — External migration policy regression coverage

Seven actual SQLite/filesystem cases pass under integration ASan/UBSan. This is
a tests-only verification of existing fixes; production source is unchanged.
The fixes predate this plan, so an initially passing regression is appropriate.
No fabricated RED or new vulnerability claim is made.

The cases exercise the public migration API with private temporary directories
and an in-memory database:

- A regular0600 migration creates/inserts real data and rolls back, including
  the schema version bookkeeping.
- An outside symlink never executes. Filesystems may skip it during directory
  discovery or expose it as DT_UNKNOWN; neither path creates a schema/version.
- A world-writable migration is refused before SQL side effects.
- A discovered regular file replaced by a symlink with `../` and a sibling path
  sharing the directory prefix is refused at execution. The actual log confirms
  canonical containment rejection, not merely an unrelated SQL failure.
- A migration containing permitted DDL followed by forbidden ATTACH is rejected
  before either executes; no outside database is created or attached.
- Rollback rechecks a replaced symlink and changed world-writable mode; each
  refusal preserves the applied table, data and version record.
