# T7.27.3 — publish and restore floor-plan backgrounds without overwriting competitors

CODEQL-314/-315's rollback paths now restore the original from the held private
backup directory with atomic no-replace semantics. Publication likewise uses
no-replace: another entry appearing after the old name is vacated is preserved.
The upload is created inside the per-request private directory and retains a
descriptor duplicated from the actual exclusively created file. UUID names are
opened with O_CREAT/O_EXCL/O_NOFOLLOW using the held private-directory descriptor,
with at most eight collision attempts; creation never follows that directory
pathname again. After writing and
syncing, private-entry identity and the held parent are checked before
publication; the named publication is checked against its held upload snapshot
before updating SQLite metadata.

If metadata update fails, cleanup first moves the current public entry into a
private failed-upload slot, also without replacing an existing entry. It deletes
that entry only when it matches the held upload identity. An unknown entry is
restored without overwriting a competitor, or retained privately and logged when
restoration conflicts. The original backup is likewise retained on restoration
conflict or unsupported operation. Ordinary failures with no competing entry
restore the original and dispose only of owned upload artifacts. Successful
requests remove only the identity-matched old private backup.

The T7.27.2 fallback that opened an unproved entry with O_RDONLY/O_NONBLOCK when
O_PATH was unavailable was removed after coordinator review. Unsupported safe
pinning now returns ENOTSUP without opening a potentially special file. The
no-replace helper remains guarded SYS_renameat2, with conservative failure and
no overwriting fallback. GET, DELETE and other-MIME obsolete-file cleanup are
unchanged and outside these mapped corrections.

rollback cases and newly added regular/symlink competitor-before-publication
cases. Existing original-byte, competitor-byte, response and metadata assertions

Limits remain explicit. Filesystem publication and SQLite metadata are not one
atomic or crash-transactional operation; replacement after the final identity
snapshot is still a window. Same-UID/privileged actors can alter private
namespaces, and already-open writers can change inode contents. The private
stat/unlink sequence relies on that namespace's ownership, not universal race
freedom. Empty-directory retirement remains best effort and nonrecursive, with
a remaining check/rmdir parent-entry window. Retained artifacts are logged for
operator inspection; no persistent orphan ledger or automatic reclamation is
claimed. Logged original pathnames can become stale if an external actor moves
their parent. Other-MIME obsolete cleanup and GET/DELETE need their own scope
and are not silently covered by these passing PUT tests. Fresh scanner and
optional-profile reconciliation remain T33; no approvals or baselines changed.
