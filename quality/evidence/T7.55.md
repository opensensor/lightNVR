# T7.55 — bounded process-name read review

Status: pending review of an existing guard; no scanner dismissal or exception
approval is recorded. Production `src/core/main.c` is unchanged.

Raw T1 finding `CLANGTIDY-470e897ffa76864e` reports the newline terminator write
in `is_lightnvr_process()` (original line362, current369). The caller checks a
PID-file value before deciding whether it identifies another LightNVR process.
The classifier itself reads `/proc/<pid>/comm` into `char comm[32]` using
`fgets(comm, sizeof(comm), fp)` and returns early if that read fails.

On a successful read, fgets supplies a NUL within indices0–31. Therefore
strcspn(comm, newline) is at most strlen(comm), itself at most31, and the
terminator write stays within the32-byte array. The complete classifier is
byte-for-byte identical to scanned revision8927bc8a; static-review.json records
that comparison and hashes. This is a proposed already-bounded/false-positive
disposition, not approval and not a production fix.

The dedicated Unity test compiles the actual private classifier by including
main.c with its server entry point renamed and never invoked. Only fopen/fgets/
fclose are wrapped. Each requested proc file is replaced with an owned anonymous
real FILE stream; real fgets performs the read. No process signal, PID-file
handling, server startup or real proc access is executed.

Twelve cases cover exact names with/without newline, unrelated names and prefix
mismatches, newline-only/empty streams, bytes following a newline, embedded NUL,
31-byte and4096-byte newline-free input, open failure and a real cookie-stream
I/O error. Assertions retain the existing conservative result on unreadable
names, exact32-byte read request, successful-read termination, stream identity,
closure and expected proc pathname. These meaningful boundary controls pass
initially because the bound already exists; no failing product test is fabricated.
