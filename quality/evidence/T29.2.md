# T29.2 — Sample actual video before finalizing stale recordings

Production commit `8ad48404` stops treating nonempty files or positive container
duration as usable footage. Recovery now requires an actual error-free decoded
video frame from a local regular MP4. Invalid/unreadable files remain incomplete
and untouched. A fixed cutoff and initial maximum ID bound an increasing-ID scan,
so retained bad rows cannot trap the500-row loop or let concurrent inserts extend
it indefinitely. The compatibility query entry point remains available.

Age is not proof that a recording stopped. A registered continuous writer or
live MP4 recording thread conservatively excludes that stream's old candidates
from both finalization and pruning. No general writer-lifecycle redesign is
claimed; uncertain candidates are retained.

## Exact probe limits

The check uses the MOV/MP4 demuxer with the file protocol only, one decoder
thread, at most64 packets and8MiB of sampled/read data. A one-second interrupt
callback limits interruptible demux/I/O work; it does **not** preempt decoder CPU
or guarantee a blocked filesystem syscall returns within that duration. A valid
result must still be inside that deadline when decoding returns. This validates
one decodable video sample, not every frame, every later payload byte or full
end-of-file integrity. Larger/slow/uncertain samples remain incomplete rather
than being asserted clean. No damaged-file repair or deletion was introduced.
