# T7.166 — names for auth, download, detection, fleet and HLS controls

All 11 remaining assigned `jsx-a11y/control-has-associated-label` occurrences
are resolved. The original six buckets held 12 occurrences; T7.161 already fixed
the HLS autoplay recovery button in commit `d8552365`. That earlier behavior
remains covered by its browser regressions in this task's full-suite run.

Auth password fields, batch download radios/filename, fleet search and HLS privacy
use existing localized labels. FullscreenButton uses the existing i18n hook and
Toggle Fullscreen label. The HLS video name combines the camera name and existing
Stream label. Input IDs/types, validation, callbacks, permissions, transport,
privacy confirmation and page-owned media controls remain unchanged. No locale,
dependency, suppression, baseline or exception changed.

DetectionOverlay has a named image wrapper around its backing canvas. The wrapper
covers the same parent box, is pointer-transparent and retains z-index 2. The
original canvas/ref/class/styles and drawing code remain intact; the backing
canvas is hidden from assistive technology to avoid duplicate semantics. The
name combines the camera name and existing Detections label. `enabled` controls
polling, not visibility: zones remain visible when polling is paused. Parent
conditions continue to remove the overlay when disabled/hidden/zoomed as before.
This names the rendered graphic; it does not claim a text equivalent for each
box/zone or broader keyboard-editing accessibility.

## Tests first and correction evidence

The direct producer wrote tests before implementation because no independent
writer slot was available. `red-node.log` has seven name/graphic failures and
two passing existing visibility controls. `red-all.log` has 12 meaningful
failures and four passing controls: missing explicit names, unlabeled fullscreen
icon, ambiguous download modes, missing detection graphic semantics and an empty
playable HLS Video AX name. Existing password redirect and fleet search behavior
already pass before production changes.

The first implementation passed 16 focused cases and the full frontend suite,
but the no-new-warning check caught an additional
`jsx-a11y/no-interactive-element-to-noninteractive-role` warning from putting
`role="img"` directly on canvas. The failed report is retained as
`lint-direct-canvas-role.json`. The coordinator approved the bounded wrapper
correction within the existing component ownership. New wrapper/backing-canvas
assertions failed first (`red-wrapper.log`, two failures), then passed after
moving image semantics to the wrapper. The final lint report has no new rule or
suppression, and the original drawing implementation is unchanged.

The final focused suite has **nine Node and seven Chromium cases**. Browser tests
render actual Preact components with built live/streams/recordings/login CSS.
Auth/download/privacy requests and query datasets are synthetic fixtures. HLS
transport effects and transient playing state are fixture-controlled, as in
T7.161; unrelated child widgets are explicit stubs. Rendering, native activation,
privacy confirmation/state, actual DetectionOverlay drawing and download helpers
remain real component code. Detection polling is stubbed; paused polling still
uses real fetched zone geometry and drawing. No live server/media acceptance is
claimed.

Coverage includes:

- Three password fields retain autocomplete, length and disabled state. Mismatched
  confirmation makes no request; valid synthetic credentials produce the exact
  PUT once, disable fields, clear auth state and navigate to the expected login URL.
- Native download modes retain keyboard selection, conditional filename presence,
  whitespace trimming and `.zip` suffix normalization. ZIP requests, status polling,
  busy Cancel/filename guards, result download and sequential filenames are exact.
  Anchor activation is observed and prevented from leaving the synthetic page.
- The named detection graphic wraps the hidden backing canvas. Real MP4 dimensions,
  canvas dimensions (320×180), identical graphic/canvas bounds, nonzero zone pixels
  and pointer hit-testing to the underlying video all pass with polling paused.
- Fleet search preserves debouncing, exact query search/page values and URL update.
- Fullscreen naming survives title removal. Enter and Space each dispatch once and
  the existing fullscreen state hides the button.
- Playable HLS Video exposes its camera-specific name in Chromium's real AX tree,
  retaining muted/autoplay/inline properties and absent native controls. Privacy
  naming survives title removal; opening/cancelling confirmation does not submit,
  confirming sends one privacy-only PUT, busy confirmation stays disabled and query
  invalidation happens once. Forbidden privacy controls remain absent and no
  fullscreen action is triggered by those controls.
- Existing HLS detection toggling removes/reinstates the named graphic; hidden
  overlays do not add a misleading accessible image. Prior media gesture, keyboard,
  coarse-pointer, dialog and shared-control browser suites remain enabled in the
  broad regression run.
