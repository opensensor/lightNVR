# T7.27.1 — preserve unknown floor-plan backup artifacts

Background PUT no longer unlinks the predictable legacy .bak name. When a
same-type old background exists, this request creates a unique mkdtemp directory,
opens it with O_DIRECTORY/O_NOFOLLOW, and verifies matching held/named identity,
current ownership and 0700 access permissions. Its private original entry is the
backup for this attempt. Unknown legacy regular files and symlinks are untouched.
GET/DELETE behavior, schema and other file-serving paths are unchanged.

The permitted fixture observation change was documented to the coordinator
before implementation: failing rollback tests now observe the actual private
backup destination rather than require a legacy .bak filename. Original-byte,
competitor-byte, response and metadata assertions remain. This change does not
make the four still-failing identity/rollback cases pass.

Before implementation, the producer plus new symlink/creation-failure controls
ran RED in native-bb38f6db5b5b: 11 cases, 7 failures. Fault review then exposed an
unsafe draft cleanup assumption: a directory rejected for changed permissions
could still be removed. The added control failed in native-9c41563621cd (12 cases,
5 failures). Cleanup now requires successful private-directory validation; a
rejected or nonempty directory is retained and its location logged. No recursive
cleanup is performed. Empty-directory removal is best effort and still has a
pathname identity-check/rmdir window; this is not universal parent-writer safety.

failures, plus all four existing API and four database cases passing:
