# T7.161 — native actions and media keyboard alternatives

All eight assigned `jsx-a11y/click-events-have-key-events` occurrences are fixed
in the six owned components. Changes distinguish actual actions from media
pointer-gesture boundaries. Existing translated labels are reused; no new
locale keys, dependencies, suppressions, exceptions or shared tests were added.

- GridPicker cells are native, named `type="button"` actions. Their dimensions,
  hover preview, existing limit guard, onSelect coordinates and close behavior
  remain. Native disabled semantics mirror the existing over-limit condition.
  The existing generated grid is capped at six by six, so over-limit cells are
  not actually produced; tests verify the 36-cell cap rather than claiming an
  unreachable disabled-cell branch was exercised. Keyboard focus is visible.
- Health cards contain a named native disclosure button with aria-expanded,
  positioned over the card. Metrics/headings remain readable siblings, outside
  the button. The button's stacking order preserves whole-card pointer clicks
  despite metrics with opacity creating their own stacking contexts.
- StreamCard's selection-mode snapshot action is a native overlay button with
  aria-pressed. The existing checkbox is a separate sibling above it. The old
  container handler and checkbox's now-unneeded stop-click handler are removed;
  a checkbox action dispatches once, without triggering the snapshot button.
  Non-selection presentation and permission-controlled checkbox/action rendering
  are unchanged.
- StreamsView's ONVIF-discovery and custom-name header crosses are native Close
  buttons. They retain the existing setters and dismissal behavior; no new
  backdrop, Escape, saving or focus-trap policy is introduced for these dialogs.
- HLS autoplay recovery is a native Play button. Native activation calls the
  original play promise and state update once. The surrounding tile's existing
  interactive-target guard prevents that action from also entering fullscreen.
- HLS/MSE outer containers are presentation boundaries for existing tap,
  double-click and mobile/zoom gesture delegation. No generic keyboard handler
  or parent button role is added around videos/nested controls. Every fullscreen
  shortcut has a native keyboard counterpart: the existing toolbar button is
  explicitly named, or a focus-only button appears when that toolbar button is
  not rendered (HLS hidden controls; MSE hidden/loading/error/not-playing states).
  The fallback remains visually clipped until keyboard focus, then appears with
  a visible outline. The callback receives the same stream and actual cell.
- Under coarse-pointer mobile CSS, the existing control group reveals with
  focus-within and hides again after focus leaves, while preserving the normal
  hidden-chrome appearance. This only adds utility classes to the owned groups;
  no shared stylesheet was edited.

## Tests first, observed failure and correction

Tests were written directly before source changes; no independent writer slot
was available. `jest-red.log` records eight failures matching the missing native
controls/boundary alternatives plus one passing non-selection control.
`browser-red.log` records the keyboard failures for grid, health, snapshot,
custom-name Close and missing fullscreen alternatives. Its initial ONVIF selector
resolved the already-native footer Close, so that passing case was not counted
as proof for the header; the final selector targets the actual header and the
header-specific Node assertion was already RED.

`coarse-red.log` demonstrates that HLS controls remained opacity zero after
keyboard focus. The old MSE glyph button also did not resolve by the desired
localized accessible name. Final tests use explicit names and verify coarse
pointer CSS, opacity zero/pointer-events none without focus, opacity one/
pointer-events auto during focus, native activation, and hiding again on blur.

The first implementation passed 17/18 focused cases but failed the health-card
pointer check after keyboard toggles. This was a real defect in the proposed
overlay, not a fixture assumption. Captured pointerdown/up/click targeted an
opacity-styled metric DIV while keyboard clicks targeted BUTTON
(`health-events-detail.log`). A z-index on the overlay fixes the stacking order.
The final test requires exactly three native clicks and three state transitions
(Enter, Space, pointer); the readable heading remains outside the button.

The browser supplement uses actual Preact rendering, component handlers and
built live/streams CSS. Explicit fixtures replace network/query/auth responses,
transport/telemetry effects, zoom/mobile hook state and unrelated child widgets.
The browser loader seeds transient media loading/error/playing and dialog-open
states in test-only source so those branches can be exercised without media or
ONVIF services. State updates and all handlers under test remain the actual
component code. No modified source is written to production by this loader.

Coverage includes native focus outlines, Enter/Space/pointer dispatches, grid
hover/coordinates, snapshot versus checkbox selection, permission-controlled
absence, header Close targets, loading/error/hidden-toolbar alternatives,
focus-only geometry, tap/double-click and nested-control guards, consumed mobile
taps, zoom guards/reset, HLS autoplay recovery and coarse-pointer focus visibility.
All pages assert zero uncaught errors. This is component behavior evidence, not
live HLS/MSE transport, camera, gesture-recognition or backend acceptance.
