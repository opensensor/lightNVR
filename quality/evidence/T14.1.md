## Scanner producer

`scanner_run.py --spec <json> --root . --reports <fresh-output-dir>
--expected-revision <full-commit-sha>` accepts argv arrays and executes commands
without shell interpolation. The version command must succeed and produce data.
Each scanner command preserves stdout/stderr, records its real exit and timeout,
and declares its report outputs. Existing reports or a duplicate scanner record
are rejected without overwriting evidence. Timeouts kill only the subprocess's
own process group. Manifests are written atomically; callers use one directory
per CI job and merge completed jobs later, not concurrent writers to one file.

Example specification (the sources are appended by the runner, not merely
counted from a candidate inventory):

```json
{
  "scanner_id": "clang-tidy",
  "version_command": ["clang-tidy", "--version"],
  "commands": [{
    "argv": ["run-clang-tidy", "-p", "build/analysis"],
    "append_scope_files": true,
    "stdout_report": "clang-tidy-report.txt",
    "reports": ["clang-tidy-report.txt"],
    "accepted_exit_codes": [0],
    "timeout_seconds": 1800
  }],
  "scope": {"kind": "invocation-files", "files": ["src/core/config.c"]}
}
```

`accepted_exit_codes` describes process execution only. The policy independently
checks every command's exit against its own accepted codes and inspects findings.
For example npm audit's findings exit 1 can be accepted as tool execution without
accepting the vulnerabilities. A later failing command cannot be hidden by an
earlier successful command or by a stale report.

Supported evidence origins:

- `eslint-json`: exact filePath entries in the actual ESLint JSON report.
- `invocation-files`: the runner appends all recorded source files to every
  command. Tool diagnostics still determine complete versus partial analysis.
- `npm-lockfiles`: actual npm audit working-directory lockfiles, separately
  declared all/prod reports; these are input artifacts, not invented source-file
  coverage.
- `file-list-report`: a declared fresh tool-produced JSON file containing files.
  Extra evidence files use a command's evidence_outputs array and must not exist
  before execution; they are not accidentally parsed as findings reports.
- `codeql-source-archive`: actual src.zip entries, with matching hashes against
  checkout files and a hash of the archive. External files are counted as omitted
  rather than read or exposed. GitHub documents src.zip as the archived scanned
  sources in [CodeQL coverage troubleshooting](https://docs.github.com/en/code-security/reference/code-scanning/troubleshoot-analysis-errors/fewer-lines-scanned-than-expected).
- `image`: tool-reported imageName/imageID from SARIF, preserved as targets;
  image scans do not claim a fictitious source-file count.

Candidate-only scope is not accepted. Report/source paths cannot traverse outside
their roots or follow symlinks. Report and evidence hashes are checked again by
the findings gate; source hashes preserve the exact checkout input provenance.

## Required check and partial lane

With require_run_manifest enabled, `findings.py --check ...
--expected-revision <full-sha>` requires valid run/scanner revision, actual command
records, tool version, ordered timezone-aware execution interval, hashed report
paths, and nonempty supported scope. Wrong revision, missing metadata, tampering,
zero scope and malformed reports fail closed. The checker does not silently infer
HEAD or rewrite a baseline. A report manifest cannot redirect reads outside its
artifact root, even when manifest enforcement is not enabled.

`findings_lane.py --reports <dir> --scanner <id> [--scanner <id> ...]
--expected-revision <full-sha>` projects inventory and policy to explicitly
selected scanner IDs. It enforces the same approval and findings rules plus
required provenance. Output is PARTIAL, status is partial-pass/partial-fail,
omitted expected scanner identities are listed, and global_verdict is null.
There is no update-baseline or release mode. Even selecting all scanner IDs does
not issue a global verdict. Only the full findings.py check covers every expected
scanner. The test suite proves that a passing ESLint lane still fails the global
check when the expected CodeQL report is absent.

T14 must wire real scanner lanes and report artifacts; T15/T35 must retain the
full coverage gate. Missing remote/private/sanitizer evidence and unapproved
exceptions must remain visible failures, not fabricated clean artifacts.
