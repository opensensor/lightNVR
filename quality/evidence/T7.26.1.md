# T7.26.1 — atomic no-overwrite migration publication

The mapped CODEQL-310 check-then-rename cause is corrected: filesystem copy
publication uses guarded `SYS_renameat2` with Linux `RENAME_NOREPLACE`, replacing
the final pathname absence check followed by overwriting `rename`. A regular
file or symlink appearing before publication is retained, with source bytes and
recording metadata unchanged. Collision retains the existing terminal failure
classification; unsupported or other publication errors retain retry behavior.

The helper does not require a libc `renameat2` export and has no overwriting
fallback. Missing syscall support, ENOSYS or unsupported filesystem EINVAL
leaves the source and temporary copy available; no destination metadata is
committed. On collision the existing temporary-removal behavior remains for now;
the focused control also injects its failure and confirms that the source and
competing destination are still untouched. Temporary identity and subsequent
abandoned cleanup remain the separately ordered T7.26.3 and T7.26.2 work.

Tests were extended before the source edit. The original producer assertions are
unchanged. New fault cases cover ENOSYS, EINVAL, I/O failure, and failed temporary
cleanup after collision. The exact syscall wrapper forwards five typed arguments
only for `SYS_renameat2`; any unexpected syscall fails the test. File replacement
is injected immediately before the atomic call, so removing the old lstat does
not remove the test's race stimulus. All files/SQLite targets are disposable.
