# T7.2.4 — Settings and system shell boundaries

This tests-only task verifies current successors of the command-injection
mitigations confirmed in original advisory fix d558e69d. The settings handler
still validates primary storage, optional HLS and backup-hook paths; the system
endpoint now reads cached telemetry and DB recording-byte totals instead of
running `du`. The filesystem collector uses stat/statvfs directly, and optional
process inspection scans `/proc`. Neither handler contains system/popen calls.

`reason_not_testable` for a new-production RED/GREEN cycle: existing-fix
verification may initially pass; no unsafe historical source was restored.
Tests were written before execution, with production source read-only. The
coordinator produced the tests directly because all worker slots were occupied.

Seven focused cases use a private SQLite database and owned temporary paths:

- Valid absolute paths containing spaces retain exact values at the persistence
  boundary. HLS override supports both a value and the documented empty reset.
- A backup-hook path is stored without executing it in the settings request.
  Actual later backup-hook execution is outside this task's claim.
- Relative paths and empty primary storage are rejected. Every prohibited shell
  metacharacter is checked independently in each of the three path fields,
  requiring HTTP400, no save and unchanged values for those fields.
- The actual system-info response succeeds without system/popen execution. This
  is the cached HTTP path, not a claim it freshly samples the configured path.
- The actual filesystem collector samples an owned directory with semicolon
  and spaces in its name, returning the same capacity as direct statvfs. The
  pathname remains data; system/popen wrappers record zero calls.

Only save_config is replaced at the persistence boundary, avoiding writes to
host configuration. Public settings parsing, validation, configuration updates,
response creation, telemetry collection and real SQLite initialization execute
normally. Shell wrappers refuse any attempted execution and count it. These
assertions establish the named system/popen boundaries, not every conceivable
process-creation API. They do not claim whole-request atomicity for mixed
unrelated settings, actual config-file durability, or arbitrary filesystem race
freedom. Fixtures are removed and the database/config allocation is closed.
