# T28.1 — unavailable legacy roots preserve metadata

Implemented the bounded durable-deletion fix in `src/storage/storage_deletion.c`.
A missing unattributed legacy object is acknowledged only when its pathname is
lexically below the configured storage root (component boundary, no parent
traversal) and that root currently stats as a directory. Otherwise the existing
deletion journal retains retry_wait and metadata. Real unlink success and
attributed target mount guards are unchanged. On root restoration the ordinary
journal worker can retry and complete deletion.

This is deliberately not persisted mount identity: an unmounted filesystem whose
empty mount-point directory remains cannot be distinguished by stat(directory).
That case is **not solved**. Unknown/unconfigured legacy roots remain pending
rather than asserting file absence. Existing outside-root files can still be
removed normally; this guard changes only ENOENT acknowledgement. No schema,
public API, storage architecture or dependency changed.
