## Added coverage

- The existing production watchdog loop now tests five failed self-restarts,
  exactly 300 simulated cooldown ticks, a retry afterward, and interruption by
  shutdown after seven cooldown ticks without another retry. Only existing
  reader/sleep seams are used; no real five-minute delay is required.
- Three consecutive two-second 24fps MPEG-4 segments are actually decoded.
  Assertions check packet/frame counts, exact source boundary timestamps,
  packet cadence within one timebase tick, and identical bytes for the one
  deliberately shared boundary keyframe. Existing audio/watchdog tests remain.
- The operational runner starts a fresh NVR plus an independent loopback
  go2rtc/FFmpeg source, disconnects/restores the actual RTSP socket, and checks
  three complete recordings before and after restore. Separate video-only and
  H.264/AAC scenarios use explicit deadlines and thresholds from
  `tests/fixtures/eng/media/scenarios.json`.
- The AAC case induces emergency pressure through its private NVR's configured
  thresholds above measured free space. The real statvfs/controller/pause path
  runs. Private fixture rows are protected, no new recording opens while the
  source restarts under emergency pressure, and restoring thresholds reports
  normal before recordings resume. No host volume is filled or remounted.
- ffprobe checks codecs, per-stream monotonic DTS, keyframe starts, packet
  counts, duration, database time interval and exact byte size. FFmpeg fully
  decodes selected files with `-xerror`. Sequence checks reject missing
  segments, excess gaps/overlap and more than one repeated boundary frame.
- Every native target has an explicit 30-second timeout and media label.
  T15.3 owns adding writer-watchdog/timestamps/faststart to the existing CI
  build/CTest list; this producer does not claim a hosted or scheduled run.

The established recorder contract intentionally retains one boundary keyframe.
The first added count assertion expected 48 packets and observed 49; review
rejected that zero-overlap assumption. The final test permits exactly that one
shared frame, proves its identity and frame conservation, and still rejects
extra overlap or missing frames. No product defect or source fix is claimed for
that initial result.

## Reproduced collision and required follow-up

In `h264-aac/lightnvr.db`, rows **5 and 6** both reference
`recording_20261031_042253.mp4`:

| Row | DB start/end | DB bytes | Actual file bytes |
| --- | --- | ---: | ---: |
| 5 | 1793434973 / 1793434973 | 72731 | 94013 |
| 6 | 1793434976 / 1793434979 | 94013 | 94013 |

The log records the buffered old reader reaching EOF and completing row 5 at
04:22:53.433. The next attempt selects the same second-derived pathname, opens
it again at 04:22:56.188, and creates row 6. The earlier completed recording's
bytes are overwritten. This is independent of allowed one-frame segment overlap.
The oracle preserves `DB/file size differs` and `Missing complete media sequence`
failures; there is no skip, WILL_FAIL or accepted exception.

Bounded fix ownership should cover `src/video/recording_path.c` (second-only
filename construction), its header only if a reservation contract requires it,
and `src/video/mp4_writer_thread.c` rotation/retry callers as necessary. A new
same-timestamp regression belongs under `tests/operational/media/`, registered
in `tests/unit/cmake/eng/media.cmake`. It must prove an existing completed file
cannot be truncated, repeated same-second attempts do not share paths, and
`storage_placement_t.object_key` remains consistent with the final path.

Revalidate flat/year-month/year-month-day layouts, path-length failure, storage
placement/root and object-key attribution, restart/retry paths, existing forced
reconnect/audio/boundary cases, DB recording synchronization, playback/download
extension handling, and deletion/migration consumers that use stored paths.
Preserve `.mp4`, stream directory layout and existing recording metadata times;
no evidence supports a broad filename-consumer rewrite. The live scenario must
then pass its exact size/time/decode assertions without hiding the interrupted
old-reader tail or prematurely counting it as three valid recovered segments.
