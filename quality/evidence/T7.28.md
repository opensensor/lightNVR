## Ownership and existing guards

Public `event_router_evaluate_delivery()` reloads persisted routes, validates each
through `db_event_route_validate()`, and compiles nonempty schedule windows through
`compile_schedule()` into `timezone_load_tzif()`. Database validation restricts
the timezone to a nonempty name shorter than 65 bytes, permits only alphanumeric,
slash, underscore, hyphen and plus characters, rejects leading/trailing or doubled
slashes, and requires a regular `/usr/share/zoneinfo/<name>` file. Dots are not
permitted, so traversal components cannot pass this validation. UTC/GMT fast paths
do not read a file. Schedule selection does not supply arbitrary TZif bytes through
the route API; files are local timezone data. Tests redirect one exact fixture
name to a disposable file rather than modify system timezone data.

`timezone_load_tzif()` limits input files to 44 through 1,048,576 bytes before
allocating their read buffer. `parse_tzif_header()` rejects any of six raw uint32
counts above `INT_MAX` before conversion, transitions outside 0..4,096, and types
outside 1..256. `tzif_block_size()` uses checked multiplication/addition and must
fit the actual remaining file before either transition array is allocated. The
same checks apply to both the initial and extended v2/v3/v4 headers. Zero
transitions need no arrays. Consequently the two mapped multiplication operands
cannot reach allocation overflow, including on 32-bit size_t platforms.

Transition indexes are validated against the type count before the compiled
timezone becomes usable. An invalid index or either allocation failure frees the
read buffer and both partial arrays. Lookup's binary search stays within the
bounded transition array and uses only validated type indexes. It assumes sorted
transition timestamps; this work does not certify complete TZif semantic
conformance or alter that existing assumption. No extra product cap was added.

## Regression and execution

The coordinator authorized direct test production because all worker slots were
occupied. The 19 new cases call the real public delivery evaluator, route
validation, schedule compiler and parser. Catalog retrieval/generations and
suppression pruning use deterministic seams. Exact-name `stat`/`fopen` wrappers
redirect to owned temporary real files. Allocation wrappers observe the two array
sizes, reject any attempted oversized allocation, inject failure of either array,
and track partial cleanup; no enormous allocation is attempted. Tests assert
unchanged route/event inputs and an empty delivery plan on rejection, not that
internal cache/error counters never change.

Cases cover ordinary delivery; zero, maximum and one-past transition counts;
`UINT32_MAX` and `INT_MAX+1` raw counts; zero, maximum and one-past type counts;
type index 255 with 256 types; invalid type index cleanup; the extended header's
maximum and one-past counts; truncated data; huge leap/character block lengths;
the existing 1 MiB file limit and one-past rejection before buffer allocation;
both array allocation failures; and recovery after replacing an invalid timezone
and reloading its route definition. On this 64-bit host the huge block test
rejects by remaining file size, not size_t overflow; a 32-bit build was not run.

offline envelope omitted required `reason` and `consecutive_failures`. After
repairing the fixture, all cases passed against unchanged production code.

already prevented by the existing guards. The fixture failure is not a security
