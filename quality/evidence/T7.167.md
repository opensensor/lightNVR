## Tests first and behavior

The direct producer wrote tests before implementation because no independent
writer slot was available. `red-node.log` records eight missing-name failures.
`red-all.log` records 14 failures and two passing existing login flows. The failures
cover unnamed setup fields, stream fields/actions, snapshot after title removal,
and an empty playable MSE Video AX name. The LiveView fixture initially reversed
the existing variant/title-key mapping; that lookup was corrected to the actual
profile definitions without changing production mapping. The MSE Node fixture
also needed its existing playing-state precondition before the privacy toolbar
renders. Those fixture corrections retain all callback and permission assertions.

The final suite has **eight Node and eight Chromium cases**. It uses actual
Preact components and built index/streams/login CSS. HTTP services, unrelated child
widgets, query datasets and fullscreen-manager callbacks are deterministic
fixtures. MSE transport effects and transient playing state are fixture-controlled;
the actual media element loads the existing repository MP4 and Chromium's Video
AX node is inspected through CDP. StreamConfigModal and its AsyncButton remain
real implementations; the test parent controls currentStream through the actual
callback contract and records the state supplied to onSave. This is not a claim
about server serialization or live media/backend acceptance.

Assertions cover:

- All six login source controls across forced-MFA and separate TOTP flows, including
  six-digit filtering, autocomplete and remembered-device day interpolation.
  Real browser flows preserve stale-logout ordering, exact credential/MFA/challenge
  requests, pending remembered-device guards and successful TOTP redirect. Synthetic
  credentials are confined to the fixture origin.
- All five setup fields retain loaded defaults, original bounds and callbacks.
  Storage/performance navigation submits the exact numeric/settings payload;
  pending navigation is disabled and completion invokes the setup-status path once.
- Every reported stream field is rendered and checked for its explicit accessible
  name in Node and Chromium. Node assertions invoke all 51 original field handlers
  with exact event identity (50 general callbacks plus the threshold callback).
  Both icon callbacks remain exact and individually named.
- ONVIF, custom detection endpoint, include/exclude filtering, continuous/detection
  schedule options, audio/backchannel, retention, EPTZ, PTZ, advanced source and
  restream branches are covered. Editing preserves immutable names, hidden
  credentials remain readonly, audio policy hides its controls, and dependent
  settings remain absent or disabled under their original conditions.
- Browser field edits preserve the controlled-state save values, Test Connection
  and Refresh Models callbacks. The real AsyncButton prevents a second pending
  save. Default/custom detection endpoint transitions emit their exact values.
- Snapshot naming survives title removal; native Enter/Space invokes the custom
  callback once per activation and never activates the parent gesture boundary.
- Both live variants retain their distinct existing fullscreen names and invoke
  the fullscreen callback once through native keyboard activation; the page's
  fullscreen state remains connected to that callback.
- Playable MSE Video has the expected camera-specific name, without native controls.
  Privacy naming survives title removal; opening/cancelling confirmation submits
  nothing, confirming sends one privacy-only PUT and invalidates once, with no
  fullscreen side effect. Forbidden privacy controls remain absent.
