## Format and boundary analysis

LightNVR's `faac_adapter_open()` sets `FAAC_INPUT_16BIT`. The public encode entry point accepts `const void *`; its wrapper explicitly explains that the internal `int32_t *` is historical and that the core interprets bytes according to the configured format. The pinned API specifies native-endian interleaved `int16_t` storage for this mode, total sample counts in whole channel groups, validated source-channel map indices, and caller-owned PCM. These facts support two-byte scaling for the selected path. [Pinned upstream API contract](https://raw.githubusercontent.com/FreewareAdvancedAudio/faac/eb4928a76fd075f9bab20e8195df84f937da289b/docs/libfaac.md).

For N samples, C channels and map index m in `[0,C-1]`, reads occur at `i*C+m`. The last read is `N-C+m`, at most `N-1`, when the supplied count follows the contract. Replacing the cast with four-byte scaling would alter sample selection and could overrun correctly sized 16-bit input. This is source-based reasoning about the reported expression, not an approved scanner dismissal.

The loop nevertheless increments `src` after its final read. For a nonzero map index, the resulting pointer is `base+N+m`, beyond the input array's one-past position. It is not dereferenced afterward, but that is insufficient to claim all pointer arithmetic is valid. This is a separate source concern from the diagnostic's initial scaling inference. Ordinary ASan/UBSan access checks may not diagnose formation of such a pointer. The intermediate `int32_t *` also needs alignment review against the public 16-bit alignment contract. [Pinned upstream loop](https://raw.githubusercontent.com/FreewareAdvancedAudio/faac/eb4928a76fd075f9bab20e8195df84f937da289b/libfaac/frame.c).

No upstream fix version was established and no library update is proposed as already justified. A passing encode test cannot substitute for resolving these language-level concerns. Caller buffers shorter than their declared sample count are outside this pointer/count API contract; the wrapper has no independent allocation-length input.
