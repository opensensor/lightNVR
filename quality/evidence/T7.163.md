# T7.163 — native actions and structural click boundaries

All nine assigned click-events-have-key-events findings are resolved in the six
owned components. The change separates real actions into native buttons and
marks structural backdrop boundaries as presentation. Existing translations and
user-provided names supply accessible names; no locale keys, dependencies,
suppressions, baseline changes or policy exceptions were added.

- LiveOperatorNavigator: location selection remains its existing native row
  button, including double-click layout application. Expansion is now a sibling
  native button with the location name and aria-expanded state. A small visual
  spacer preserves the original arrow position and indentation; the independent
  button overlays that position without nesting inside the selection button.
  Expansion does not select/load a location. Camera drag behavior is unchanged.
- RecordingsGrid: the thumbnail container becomes structural. A full-area native
  play button, independent retry button and selection checkbox overlay are
  siblings. Their stacking keeps retry/selection clickable above play, while
  visual overlays remain visible. The selection wrapper needs no stop-click
  handler. Existing loading/hover frames, in-progress indicators, badges and
  recording callback arguments remain. RecordingsView.playRecording still owns
  the in-progress guard and informational toast; the card continues to call it.
- TimelinePlayer: the fullscreen prompt has a full-area native entry button and
  separate native dismiss button. Entry retains the original asynchronous
  handleToggleFullscreen callback; dismissal never enters fullscreen. The
  video/native-controls properties, mouse guard, proportional controls band,
  pointer propagation, double-click fullscreen callback and toolbar are unchanged.
  TimelinePage still supplies autoFullscreen from its URL parameter.
- Go2rtcTab: effective-config preview dismissal uses a target-only presentation
  backdrop, with click containment at that boundary instead of its inner
  stop-click div. Native Close and the settings authorization/loading behavior
  remain unchanged. This does not claim new Escape, focus-trap or dialog-role
  behavior for that existing preview.
- ClearLogsModal/RestartModal: their existing guarded backdrop handlers already
  distinguish background from content. Only role=presentation is added. Portal
  behavior, native Cancel/Confirm callbacks, Restart Escape guard and reconnection
  logic remain unchanged. SystemView and SystemControls retain their existing
  close/confirm ownership. This does not add broader modal accessibility behavior.

LiveView's existing filter/layout callbacks and SettingsView's existing settings
callbacks remain the callers. No catch-all keyboard handlers or key suppression
were introduced.

## Tests first

No independent test-writer slot was available, so tests were written directly
before implementation in `web/tests/remediation/t7_163.spec.jsx`. Initial Node
execution failed nine expected native-control/presentation assertions, with the
existing restart guard control passing (`jest-red.log`). The first browser
fixture needed missing service exports and the actual `index.html` stylesheet
entry corrected; those bundle failures are retained in `browser-red.log` and are
not product RED evidence. The corrected actual Chromium run then failed the
three missing native control lookups (location expansion, thumbnail play and
fullscreen entry), while settings/system interaction controls passed
(`browser-red-corrected.log`). Those failures preceded production edits.

Final focused browser-enabled execution passes all 14 tests, including ten Node
cases and four browser cases. Default Jest selects the ten Node cases and leaves
four browser supplements unselected. Meaningful coverage includes:

- Location expansion by Enter, Space and pointer, visible focus, expanded state,
  no filter/layout dispatch from expansion, native row selection, exactly one
  double-click layout dispatch and preserved camera drag data.
- Thumbnail play by Enter/Space/pointer with the original recording ID; native
  selection by Space/pointer with no play dispatch; independent retry by all
  three methods with exactly one load request and no playback. Real hover
  timing still preloads two frames, cycles to frame one, and resets to frame zero
  after pointer leave. In-progress playback remains delegated to the caller and
  performs no thumbnail fetch.
- Fullscreen prompt entry/dismissal by Enter/Space/pointer, one entry request,
  actual transient user activation, correct video-container target, no nested
  buttons, intact native video controls, and unchanged mouse-guard double-click
  callback/control-band geometry.
- Native portal Cancel/Confirm controls by keyboard and pointer, content clicks
  not dismissing, backdrop dismissal, Restart pending-button duplicate protection,
  active-restart Escape/backdrop blocking, read-only preview disabling, and
  preview content/Close/backdrop independence.

Browser tests mount real Preact/components and use built styles from the actual
pages. They assert zero uncaught page errors. Service/query/thumbnail responses
and the external timeline state owner are fixtures; requestFullscreen is a
recording stub so the test checks native activation and request dispatch, not a
real fullscreen transition. The video has no decoded media source; media decode,
codec behavior and complete TimelinePage shortcut behavior are not claimed.
No live API, restart, log clearing, backend server or real settings mutation runs.
