# T7.2.7 — Complete multi-source identities or reject before transport

`go2rtc_api_add_stream_multi()` now converts the positive source count to
`size_t` before adding one and checks multiplication against `SIZE_MAX` before
allocating the existing `1024 * (count + 1)` aggregate URL budget. It retains
support for arbitrary caller-provided array counts that fit; no four-source cap
was introduced. A five-source valid regression passes.

Source and stream-name values use complete allocated
[`curl_easy_escape()` encodings](https://curl.se/libcurl/c/curl_easy_escape.html),
with checked conversion to the API's `int` length and explicit rejection when
the raw value already cannot fit the aggregate budget. Each encoded allocation
is freed with `curl_free()` immediately after its append. A NULL source, encoding
failure or any truncated append exits through URL/CURL cleanup **before** perform.
The final name append now rejects overflow instead of merely logging it.

The original 3,500-byte source and 256-space name cases are accepted with their
complete identities when the aggregate URL fits. Aggregate source overflow and
the one-byte final-name overflow are rejected without any transport call. Valid
escaping, ordering, name, source count and exact-fit URL behavior are preserved.
Only this builder changed; other single-source/mutation builders and their
preexisting compiler diagnostics remain outside this task.
