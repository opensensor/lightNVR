## Scope and limits

Legacy storage has no persisted mount identity. Canonical directory availability cannot prove that an underlying filesystem has not been unmounted while its mount directory remains; this inherits the documented T28.1 limit. Attributed filesystem targets use the existing configured mount guard; targets without a required mount guard share the directory-availability limitation. Unknown and nonfilesystem storage is retained. No sentinel or filesystem-UUID verification is claimed.

The filesystem identity check occurs at processing time before unlink; it is not an atomic compare-and-unlink against arbitrary concurrent external writers. Persisted disabled state and live ownership are rechecked, not held under a single global lifecycle/filesystem lock. T27.1 uses O_EXCL path reservation so an application writer does not reuse an existing empty candidate; replacement or payload changes before processing fail safely. No claim of universal filesystem race freedom or recovery of retained pending objects is made. A pending retained object needs investigation; its guard is never cleared to force deletion.

T29.2 media validation remains bounded local sample validation, not whole-file integrity: a decoded video sample is required, with packet/byte ceilings and an interruptible I/O deadline, not guaranteed decoder CPU preemption. Invalid or uncertain media stays incomplete.
