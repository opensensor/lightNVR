# T30.1 — bounded host soak executor

The independent host executor composes the unchanged T27 video-only, T27 AAC/pressure/reconnect and T29 upgrade/record/restart/crash scenarios twice each. It archives source/binary/build/tool identities, original scenario reports/logs, per-process and grouped RSS/CPU/FD/thread samples, exit/unavailability events, and separate functional versus qualification summaries. It never builds the application, edits a budget, adopts an existing service, or nests/breaks the existing runtime lock. See `tests/operational/soak/README.md` for exact limitations and proposed TSan work.

## Qualification semantics

Exit 0 requires functional success, complete observations, passing supplied growth limits and every required runtime metric. Exit 1 reports functional failure; exit 2 reports functional success with incomplete qualification. All limits are read dynamically from `quality/runtime-budgets.json`; null limits remain unqualified. The checked-in growth limits remain null too. No physical budget or user-approved exception is created.

Host measurements are mixed-phase informational observations, not physical-device calibration, sustained leak proof or baseline/candidate comparison. NVR/managed children, synthetic source branches and browser branches are separated. CPU is one core=100%; first samples have no CPU delta. RSS sums can count shared pages more than once. Missing active samples cannot be converted to zero or dropped to claim qualification. Expected exits retain unavailable-at-exit events while closing their process windows. Periodic sampling can miss short-lived processes; idle/recording RSS phase separation and browser latency/heap metrics remain unavailable. Managed go2rtc is included in the NVR group; its synthetic lavfi FFmpeg branch is separately a source.

Media recovery/gap assertions use existing T27 tolerances and reports; no oracle was relaxed. Gap figures concern committed DB segment adjacency within each uninterrupted phase, with intentional outage excluded, while T27 retains its packet/decode checks. T29 retains its exact lifecycle assertions and normal graceful deadlines. The outer 300-second containment ceiling is an executor watchdog, not a physical recovery budget.

## Race detection assessment

Standalone TSan is **not run/unqualified**. CMake Debug injects ASan/UBSan and the current native runner has no TSan mode. The documented future experiment requires a separate non-Debug build with explicit TSan-only compile/link flags, deliberate-race and no-race controls, and dependency/runtime compatibility evidence. Application TSan cannot qualify the Go go2rtc binary; uninstrumented third-party libraries limit visibility. This task neither mixes sanitizers nor claims race freedom from functional/release runs.
