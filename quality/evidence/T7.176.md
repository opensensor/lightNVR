# T7.176 — mobile menu composite focusability

Fixed `ESLINT-BUCKET-3469a0a703cdbc12` with one production line:
`tabIndex={-1}` on the existing `role="menu"` container in
`MobileTileGestures.jsx`. This makes the container programmatically focusable
without adding a Tab stop. The existing effect still focuses the first native
child button. No activation handler, arrow navigation, duplicate key/click
handling, dependency, lint rule or exception was added.

## Role decision and scope

Reviewed the primary [W3C menu pattern](https://www.w3.org/WAI/ARIA/apg/patterns/menubar/)
and the [jsx-a11y rule documentation](https://github.com/jsx-eslint/eslint-plugin-jsx-a11y/blob/main/docs/rules/interactive-supports-focus.md).
The APG places initial focus on the first item when a menu opens. The lint rule
distinguishes focusability within a composite from a standalone control's Tab
stop and documents negative tabindex for the former. The selected change keeps
the menu a composite container and its action children native buttons.

This narrow fix does **not** claim complete APG menu conformance. Existing
arrow/roving-focus behavior and focus return are not expanded by this task.
Localized names, audio/reorder visibility, pointer containment, native action
callbacks and Escape dismissal are preserved.
