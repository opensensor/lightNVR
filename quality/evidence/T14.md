# T14 — analysis reports and blocking CI policy

Implemented locally on 2026-10-31. No workflow was pushed, dispatched, or observed on GitHub. Workflow validity and isolated runner contracts pass; hosted scanner success and repository required-check activation are **not verified**.

## Concrete integration

`Static Analysis` now runs ESLint, both npm lockfile audits (all dependencies and production only), native clang-tidy/cppcheck, reusable CodeQL C/C++ and JavaScript/TypeScript, and the reusable production-container scan on main PRs/pushes. The reusable workflows retain their manual/scheduled/tag entry points where applicable. `Analysis coverage and findings` (`analysis-coverage`) waits for every lane with `always()`, downloads only this workflow run's artifacts, rejects duplicate/wrong-revision manifests, rebases report/evidence paths, and runs the full 13-scanner findings policy. The child workflows do not fetch cross-run reports or private GitHub advisory/secret API payloads.

Each lane captures actual subprocess argv, exits, timeouts, versions, report hashes and source/target scope through T14.1. Scoped results explicitly remain partial. Report upload runs even after scanner/policy failure. `quality/findings-policy.json` now requires manifests and every CI invocation supplies the checked-out `GITHUB_SHA` as `--expected-revision`. npm/ESLint finding exit 1 and explicitly configured cppcheck/Trivy finding exit 2 are accepted execution statuses; the report policy still rejects new findings and scanner errors. No baseline, approval, owner, or expiry was changed.

CodeQL init/finalize produce an extracted database; the recorded command is the actual `codeql database analyze`, with security-extended queries and SARIF baseline file information. Scope comes from the actual database `src.zip`, whose checkout-source bytes are checked before hashing. Copying an earlier SARIF is not represented as analysis. CodeQL action upload is separate from policy enforcement. See the official [action outputs/options](https://github.com/github/codeql-action/blob/v4/analyze/action.yml), [CLI analysis guidance](https://docs.github.com/en/code-security/tutorials/customize-code-scanning/analyze-code), and [source archive guidance](https://docs.github.com/en/code-security/reference/code-scanning/troubleshoot-analysis-errors/fewer-lines-scanned-than-expected).

Native analysis uses an explicit Release compile database with SOD, go2rtc, LiteRT, Sentry, SSL and tests disabled; MQTT enabled. FAAC is initialized. The excluded feature profiles are not claimed scanned. Clang-tidy receives the compiled application translation units, and both actual output streams are captured without a masking shell pipeline. ClangTool itself emits `[i/N] Processing file`; the checker requires this progress and rejects compile errors/truncation. The [LLVM implementation](https://github.com/llvm/llvm-project/blob/main/clang/lib/Tooling/Tooling.cpp) establishes that format. Cppcheck uses `--project` and its real `Checking` progress stream for file scope because [project mode cannot also accept positional sources](https://github.com/danmar/cppcheck/blob/main/cli/cmdlineparser.cpp). Its XML completeness/coverage checks still apply.

Trivy scans only the locally built linux/amd64 Dockerfile image, with immutable identity read from raw SARIF. Other architectures/images remain explicitly excluded. `trivy version --format json` is captured before and after the scan, preserving vulnerability DB version/update metadata and supplementary database metadata; the vulnerability DB is downloaded explicitly and not updated during scanning. The [official version command](https://github.com/aquasecurity/trivy/blob/main/pkg/commands/app.go) and [metadata implementation](https://github.com/aquasecurity/trivy/blob/main/pkg/version/version.go) support this provenance. Secret scanning is not enabled by the container scan.

## Remaining truthful limits

The full gate is intentionally expected to fail until real same-revision evidence and necessary approvals exist. This workflow supplies eight scanner identities; GitHub Code Quality, Dependabot, secret scanning, repository security advisories and the sanitizer report are not supplied by these jobs. All 13 remain expected; none is silently deleted or treated clean. The existing proposed exceptions remain unapproved. Historical T1 reports cannot satisfy the newly required provenance. New compiler/database/query versions may also yield findings or incomplete scans and must be assessed from actual hosted artifacts.

The local isolated runner proves failure propagation and artifact/provenance contracts, not successful extraction/build/scanning by hosted CodeQL, Debian packages, Trivy, Docker or remote npm audit. External dependencies/authentication and disabled features may fail, which is intentional and visible. The manifest's source hashes preserve the bytes actually read; a caller-supplied revision alone does not prove a dirty local worktree equals that commit. CI uses a fresh checkout.
