# T7.59.1 — partial health-worker startup deadlock producer

**Confirmed: three real deadlock failures remain RED.** This tests-only producer
does not change production and does not reproduce the separate tier-array
scanner warning. A bounded correction must be materialized before fixing it.

## Observed interleaving

`system_health_start` holds `lifecycle_lock` while creating workers. A started
worker calls `system_health_collect_tier`, which needs that mutex. On a later
pthread_create failure, the start function clears running and joins previously
created workers while still holding `lifecycle_lock`. An already-entered
collector cannot reach the next running check while waiting for that mutex.

The test includes the actual lifecycle implementation. A pthread-create wrapper
starts real threads through a small argument-preserving trampoline. Their
mutex wrapper records entry to the actual lifecycle-lock call. Before injecting
EAGAIN for a later creation, the main thread waits for every earlier worker's
lock-entry event. Because start still owns that mutex, the interleaving is proven
by a handshake rather than inferred from a sleep. The actual pthread_join call
is also observed. No private worker tier is modified.

Each case runs in its own forked child, with no other parent threads active.
The child disables builtin collectors and hardware providers, asserts that no
provider is registered, and uses fake collectors only. A pipe preserves lock,
creation-failure and join-entry events. The parent waits at most three seconds;
on timeout it kills only its still-unreaped child PID, then reaps it. An unreaped
child PID cannot have been recycled. The containment kill is an explicit failed
result, never a successful shutdown. Teardown checks child/pipe ownership and
cleans only those owned resources.
