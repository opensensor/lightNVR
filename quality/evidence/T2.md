## Streams variants (input for T11)

All of this is in `api-inventory.streams_pilot`.

- **List:** `GET /api/streams?summary=true&surface=admin&include_admin_url=true&page&page_size&sort_by&sort_order&availability[&search]`.
  - Validated parameters (400 on invalid):
    - `page_size` 1..100
    - `sort_by` name|status|resolution|fps|recording
    - `sort_order` asc|desc
    - `surface` admin|live|lpr
    - `availability` all|live|offline|never_connected|disabled
  - Rows are filtered by `AUTHZ_LIVE_VIEW`.
  - `can_configure` is the per-row `AUTHZ_CAMERA_CONFIGURE` decision.
  - `admin_url` is opt-in, and blank unless `can_configure` is true.
  - The `live` surface adds playback and PTZ fields. `lpr` returns `{camera_uuid, name}` only.
  - The summary never carries URLs or credentials.
- **Legacy list:** `GET /api/streams` without `summary` returns an unbounded array of full
  objects. No web/js caller uses it.
- **Full edit detail:** `GET /api/streams/{name}/full` returns `{stream:{...}}`. It requires
  `AUTHZ_LIVE_VIEW`. The response has two role variants:
  - **Configure-allowed (admin model):** sensitive fields are real values. When separate ONVIF
    credentials are in use, credentials are stripped from the URL and returned in
    `onvif_username`/`onvif_password`.
  - **Live-only (viewer model):** the URL is credential-stripped (or empty), and the ONVIF
    user/password, `admin_url`, `go2rtc_source_override`, `sub_stream_url`, `detection_url`
    and `publish_url` are all empty strings. `can_control_privacy=false`.
    `has_sub_stream` still reveals that a sub-stream exists.
- **Update:** `PUT /api/streams/{name}` requires `AUTHZ_CAMERA_CONFIGURE`, checked before the
  body is parsed.
  - The accepted key list is recorded.
  - Validation: retention values -1..365, `playback_transport`, eptz, `detection_url` scheme,
    `publish_url` scheme, and size limits (413).
  - It returns 202 (async apply). `set_privacy_mode` short-circuits with 200.
  - Errors are `{"error": "..."}`.
- **Option dependencies for list/edit:**
  - `GET /api/client-config`: `default_playback_transport`, `audio_disabled`, and
    `webrtc|mse|hls_disabled`.
  - `GET /api/detection/models`: returns 403 without any configure grant. The UI filters out
    `api-detection` and disables `supported===false`.
  - `GET /api/auth/verify`: role and `demo_mode`.
  - `GET|POST /api/streams/{name}/zones` (ZoneEditor).
  - `/go2rtc/api/frame.jpeg` (card and zone snapshots).
- **Out of pilot but in the same view:**
  - Create (POST, 201), test, and clone.
  - Disable (`DELETE`) and permanent delete (`?permanent=true`, 202).
  - Enable (`PUT {enable_disabled, enabled}`) and bulk operations.
  - ONVIF discovery/profiles/test/claim and `GET /api/settings`.
  - The embedded Health, Fleet, and Events tabs.

## Live compatibility (PR #691)

This is recorded in `application-inventory.live_compatibility_pr691`.

- `LiveView` takes a `variant` of `webrtc` or `hls`. The variant profiles live in
  `utils/live-view-url.js` (`LIVE_VIEW_VARIANTS`) and set per-variant localStorage prefixes,
  query keys (`webrtc-summary`/`live-summary`), the tag filter style, and label keys.
- `index-page` chooses `webrtc` unless WebRTC or go2rtc is off. It also gates SetupWizard.
- `hls-page` always uses `hls`.
- Transport selection works in this order: a `?mode=` override, then `/hls.html` implying HLS,
  then the first offered transport when Auto is disabled. The tabs are built by
  `getLiveTransportTabs()`.
- `WebRTCView.jsx` no longer exists and must not be recreated.

## Gotchas

- Router semantics:
  - `#` matches a possibly-empty run of characters that contains no `/`.
  - Routing is first-match, method-filtered.
  - An unmatched `/api/*` falls through to static resolution and gets a 404 JSON response. It
    never gets 405.
  - The whole `/go2rtc` namespace goes to the proxy thread whatever the method.
- The Playwright `go2rtc` project matches no files. `go2rtc.api.spec.ts` runs under `api`.
- Several `StreamsView` fetches use raw `fetch` (`/full`, zones) and bypass the `fetchJSON`
  timeout, retry, and 401 handling.
- `Toast.jsx` duplicates the `ToastContainer.jsx` API and has no importers.
- Other agents shared this checkout during this task: `quality/findings.json`,
  `quality/scanners.json`, and `quality/web-budgets.json` belong to T1/T4. Only the three T2
  files were committed.
