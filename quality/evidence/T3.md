### Baseline failures: host environment, not code (BLOCKER for the as-specified command)

The as-specified build fails these 7 tests:

- `test_audio_transcoder`
- `test_mp4_forced_reconnect`
- `test_mp4_audio_recovery`
- `test_hls_cleanup`
- `test_mp4_segment_boundaries`
- `test_audio_voice_filter_faults`
- `test_udt_recording`

**Root cause: FFmpeg header/library ABI mismatch on this host.**

- `/usr/local/lib/pkgconfig/libav*.pc` and `/usr/local/include/libav*` come from a stale FFmpeg 7.1 install (libavcodec 61.19.101). Its libraries were moved to `/usr/local/lib/ffmpeg-local-backup`.
- pkg-config searches `/usr/local` first, and gcc searches `/usr/local/include` before `/usr/include/x86_64-linux-gnu`. The build therefore compiles against the 7.1 headers.
- The linker and loader resolve the Ubuntu `libavcodec-dev 8.0.1` libraries instead (`libavcodec.so.62`, `libavutil.so.60`). `ldd build/eng-T3/bin/test_mp4_audio_recovery` shows this.

The mismatch shows up in three ways:

- **`avcodec_open2` returns −22.** The encoder sees "Picture size 32x0 is invalid" because the `AVCodecContext` layout differs between the two versions. This hits `test_mp4_audio_recovery` (4/4 cases) and `test_hls_cleanup` (2/8 cases).
- **ASan SEGV in `av_buffer_unref` (libavutil.so.60).** This follows "Failed to allocate resampled frame buffer: Invalid argument", caused by the `AVFrame` layout. It hits `test_audio_transcoder`, `test_mp4_forced_reconnect` and `test_audio_voice_filter_faults`.
- **Leak reports** (`test_mp4_segment_boundaries`) and **transcode failures** (`test_udt_recording`) come from the same mismatch.

**Diagnostic control build.** This build uses the same flags, but `PKG_CONFIG_LIBDIR` points at the system `.pc` files and `-isystem /usr/include/x86_64-linux-gnu` is added. It ends up with FFmpeg 8.0.1 headers and libraries on both sides:

```
build/eng-T3/sysffmpeg-debug: ctest full -> 153/153 passed (exit 0, 123 s)
                              targeted 6 -> 6/6 passed (exit 0)
```

So the baseline has **no code failures** for the lean feature set. On this host, the as-specified command is reproducible only after one of these fixes:

- removing or renaming the stale `/usr/local` FFmpeg headers and `.pc` files (needs sudo; not done), or
- exporting the two overrides above.

T13's `run-native.py` should pin dependency resolution, or detect a header/soname major mismatch and fail. Otherwise later tasks will report these failures as regressions.

Per-test status for both builds (`baseline_as_specified`, `baseline_system_ffmpeg`) is recorded under `tests[]` in `quality/operational-coverage.json`.

### Kinds of evidence

- **Mocks.** Many recovery tests replace functions at link time with `-Wl,--wrap`:
  - `test_mp4_forced_reconnect` wraps `record_segment`, `av_usleep`, config lookup, storage pause and path placement.
  - `test_mp4_recovery_watchdog` wraps `sleep` and the writer start/stop/is_recording functions.
  - `test_mp4_audio_recovery` wraps `av_read_frame` and `cleanup_audio_transcoder`.
  - `test_api_handlers_recordings_playback` wraps 7 functions.
- **Real media.** Two sources are used: media encoded in-process with the FFmpeg library (MPEG-4/G.711), and `tests/integration/fixtures/recording.mp4` (64x64, 1 fps). Playwright uses a real server and go2rtc with `ffmpeg:virtual` test patterns. No test drives a real RTSP disconnect.
- **Hardware.** No lane has any hardware evidence.

**Omitted features are not counted as covered.** The lean baseline compiles out SOD, LiteRT, go2rtc and MQTT, plus libyaml on this host. Production containers ship LiteRT and SOD-dynamic, but no CI lane tests them.

### Numerical limits that need calibration

These are listed in `calibration_limits`. They are production constants, not acceptance limits. Each scenario deadline must be derived from them and measured on the T5 target:

- 5 s dead threshold, 5 restarts, 300 s cooldown, 120 s healthy reset
- writer inactivity `max(45, segment+15)` s, with a 60 s initial grace
- keyframe wait 5 s / 1 s
- reconnect backoff 500–30000 ms
- shutdown watchdog 900 s
- disk pressure thresholds at 20/10/5% free
- 300 s retention budget
- 60/900/21600 s storage cadences
- health timeout 3000 ms
- benchmark gate: heap ≤ 512 KiB and CPU ratio ≤ 0.005

### Candidate bounded C improvements (for T31)

1. **C1 `stream_state` transitions.** The state machine has 6 states but no transition table or transition tests. The test file references `STREAM_STATE_*` exactly once. Proposal: extract a pure transition function.
2. **C2 `/proc` and cgroup parsing in `api_handlers_system.c`.** This code duplicates the injectable `linux_cgroup` and `linux_process` collectors and cannot be tested with fixtures. Lowest risk; matches the PRD's `/proc` example.
3. **C3 `/proc` probes in `go2rtc_process.c`.** There are 8 hard-coded sites in a heavily changed file (32 commits since 2026-04).
4. **C4 `storage_reconcile_incomplete_recordings()`.** Untested, and it mixes the finalize/prune decision with I/O.
5. **C5 a `statvfs` provider seam in `storage_manager.c`.** This would let T28 inject faults; the same pattern already exists in `storage_target_health` ops.

The telemetry collectors (`src/telemetry/collectors/*`) already take a `proc_root`, are tested against fixtures, and look sound. They should not be refactored.
