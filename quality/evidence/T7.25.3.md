## Behavior

Retention keeps its directory descriptor throughout collection and pruning.
Every eligible regular `.sqlite3` file is opened with `O_PATH | O_NOFOLLOW` and
its device/inode, size and nanosecond mtime are recorded. Those original
descriptors remain live through deletion; a changed published name is never
reopened and relabeled as the original selection. Symlinks and nonregular files
do not count toward retention. Sorting the basenames preserves the previous
lexicographic timestamp order and newest-N selection within the common parent.
Repeated collected names abort before deletion; distinct hard-linked names still
retain the existing filename-count semantics.

The existing private quarantine and no-overwrite restoration mechanism now
accepts that pinned selection. Before moving, it verifies the pinned snapshot;
after moving, it verifies the object in the held private directory before
unlinking. A replacement is restored without overwriting a competing published
entry. Failed restoration retains the object in the logged quarantine. The pass
stops at the first deletion uncertainty. Stale temporary-artifact cleanup uses
the same narrow helper and preserves its existing missing-entry behavior.

Collection needs O(number of eligible backups) temporary descriptors and memory.
There is no arbitrary backup-count cap. Checked allocation, actual open failures
(including EMFILE), failed metadata reads and failed enumeration abort collection
before any deletion, close every pin and retain the backups. Capacity doubling
and element-size multiplication are checked. This may defer retention under
resource pressure; it does not silently select a partial inventory.

## Limits

`O_PATH` and atomic no-replace rename support are required for destructive
cleanup. Unsupported operations retain objects and report incomplete pruning;
there is no overwriting fallback. Quarantines can remain after failed restoration
or a crash, and unknown leftovers are not recursively cleaned.

The existing initial configured-parent resolution is unchanged. This is not a
general containment policy or protection against a compromised runtime UID,
privileged actors, actors able to modify the private directory, or writers with
already-open file descriptors. Size/mtime are snapshots rather than writer
locks. Private-directory empty cleanup retains its existing best-effort identity
check followed by nonrecursive `AT_REMOVEDIR`; it does not provide atomic
compare-and-remove identity against an arbitrary concurrent parent writer.
