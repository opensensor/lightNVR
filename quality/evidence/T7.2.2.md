## Test boundaries and isolation

- Public `qb_init`, `qb_add_column`, and `qb_build_select` use real SQLite schema
  discovery. Generated 63-character column names exist in a real in-memory
  table; no builder internals are changed by the tests. Ordinary WHERE/ORDER,
  exact 4,095-byte query, one-byte excess, large WHERE/ORDER and 62 fitting
  columns pass. Guard words also remain intact at the query buffer boundary.
- Public zone save/get uses real SQLite transactions with a private in-memory
  table. All 32 normalized points round-trip. Large finite coordinate formatting
  exceeds the 2,048-byte JSON buffer and is rejected with the previous row
  preserved; zero and negative counts similarly roll back. The large coordinates
  are a direct serializer boundary probe, not a claim that the HTTP API admits
  non-normalized geometry.
- Public `go2rtc_api_add_stream_multi` uses actual libcurl URL options and
  production escaping. Only `curl_easy_perform` and response-code retrieval are
  replaced with a successful synthetic upstream. The seam captures the exact URL
  set on the handle, then independent libcurl decoding verifies each source and
  name byte-for-byte, including count/order. No socket, camera or remote service
  is contacted. A rejected oversized input must send **zero** requests; accepting
  it is allowed only if the entire identity survives. Valid escaping, a maximum
  255-character stream name and an exact 2,047-byte aggregate URL pass.

The only database seam supplies the private SQLite handle; schema checks,
serialization and transactions run production code. Each test closes its DB,
finalizes statements, cleans up go2rtc API state and frees captured URLs. All
inputs and identities are synthetic. This is URL-construction evidence, not
end-to-end remote go2rtc interpretation.
