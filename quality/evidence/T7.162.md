# T7.162 — native shared actions and structural dialog boundaries

All eight assigned `jsx-a11y/click-events-have-key-events` occurrences are
resolved in the six owned components. Existing translation keys provide new
control names; no locale, shared test, dependency, baseline, exception or
suppression was changed.

- ToastContainer: the dismissible toast is now a native button with its existing
  message and a localized Close/name association. The original removal path,
  timer, styling and message remain. Text alignment and focus outline are
  explicit; Enter, Space and pointer remove only the selected notice.
- UI: SnapshotPreviewModal and VideoModal backdrops have presentation roles.
  Their existing target-only click dismissal, descendant controls and document
  Escape listeners are unchanged. No parent keyboard activation is added.
- common/ModalDialog: ModalShell's propagation boundary has a presentation role.
  The semantic dialog section, initial focus, focus trap/restore, Escape rules,
  target-only mousedown dismissal and click stopPropagation remain unchanged.
- WebRTCVideoCell: its media container is a presentation boundary retaining
  tap/double-click/mobile/zoom delegation. Its existing native fullscreen button
  gains an explicit localized name and focus outline. When controls are hidden,
  a focus-only native counterpart invokes the same stream/cell callback, so
  keyboard users retain the pointer shortcut's action without making the video
  container a button. Focus-within reveals the existing coarse-pointer controls
  while focused, preserving hidden-chrome opacity/pointer behavior otherwise.
- ZoneEditor: the reported sidebar card remains the delegated selection
  boundary, with a presentation role. A visible native Select/zone-name button
  supplies keyboard selection and aria-pressed feedback, bubbling exactly once
  to the original handler. Existing field/card clicks still select the card.
  The canvas, polygon math, draw/edit/delete handlers and save flow are untouched.
  This bucket does not establish keyboard editing support for the canvas.
- LanguageSelector: a native trigger retains the focus-based dropdown, and
  native option buttons replace list-item click handlers inside structural list
  items. Locale/null payloads and post-selection blur remain unchanged. Labels
  reuse the language key and existing locale code/native-name text; desktop and
  mobile rendering retain their surrounding structure.

was available. `jest-red.log` records nine failures covering all assigned
surfaces/branches. `browser-red.log` demonstrates missing native toast/language/
zone actions and hidden-toolbar WebRTC action. Snapshot/video behavior controls
already passed before implementation.

Two initial shared-dialog browser controls ran before Preact effects had settled.
The corrected pre-change run (`dialog-controls-before.log`) passes both: initial
focus/wrapping/restoration, confirm-disabled behavior, inside-to-backdrop drag,
pending submission Escape/backdrop guards and exact input/checkbox payload.
These existing behavior controls remain assertions, not requested policy changes.

The first broad post-change run found one additional test timing problem: it
filled TextInputDialog before its mount effect applied initialValue, so the
submitted value reverted to Entry. The final fixture waits for the observable
initial input focus/value before editing; the exact trimmed Renamed/true submit
assertion remains. No source lifecycle policy or guard was changed to pass it.

The focused suite has nine Node and nine actual Chromium cases. Browser evidence
uses actual Preact components, built live/streams/recordings CSS and actual shared
ModalShell implementations. Queries/auth/media loading, WebRTC transport effects,
zoom/mobile hook state and unrelated child widgets are explicit service fixtures.
The WebRTC test loader seeds playing/error state without altering production
files; handlers and state updates under test remain the real component code.
Zone snapshots use a synthetic SVG of known dimensions, with real canvas drawing
and existing geometry. No live backend/media acceptance is claimed.

Assertions cover:

- Enter/Space/pointer and focus visibility for toast, locale and zone actions;
  independent toast removal and exact locale payloads, with dropdown blur/closure.
- Initial dialog focus, forward/backward Tab wrapping, focus restoration and
  native confirmation dispatch once. Disabled confirmation remains disabled.
- Inside-to-backdrop mouse drag does not dismiss; pending input/checkbox/Cancel
  controls stay disabled and Escape/backdrop are guarded; final submit values are
  exact and existing false-result behavior retains the dialog.
- Snapshot Download and native video controls remain inside the modal; Escape
  and direct backdrop pointer clicks dismiss once.
- Zone selection generates exactly one card click per native button activation,
  with field click/checkbox updates preserved. Save contains the unchanged
  polygon plus edited name/enabled state. A separate pointer-delete mode control
  uses the rendered canvas/letterbox geometry and saves exactly one empty list.
- WebRTC fullscreen controls remain available in hidden/loading/error/playing
  branches; keyboard and pointer shortcuts dispatch once, zoom suppresses the
  gesture, and coarse-pointer controls reveal on focus and hide on blur.

Every browser page asserts zero uncaught errors. The broad final command enables
prior T7.161 media and T7.164/T7.165 modal browser suites as shared-consumer
regressions, alongside the full unit suite and existing zone geometry tests.
