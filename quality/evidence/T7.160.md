# T7.160 — profile actions use native buttons

Fixed `ESLINT-BUCKET-366138c5d194685c` in `Header.jsx`.
The profile control is now a native `button type="button"`; disabled profile
controls use the native disabled attribute and retain their callback guard.
Navigation controls remain anchors with their actual destinations. Shared
classes, IDs, translated labels/titles, profile callback and mobile-menu closure
are preserved. No dependency, lint rule, baseline or exception was changed.

## Reproducer and tests first

The raw T1 artifact
`build/eng-artifacts/T1/actions/static-analysis-41176542849/web-jsx-a11y.log`
records the Header warning at line260: anchor used as a button. The mapped
fingerprint is `eslint-bucket:jsx-a11y/anchor-is-valid:web/js/components/preact/Header.jsx`.
Tracing `renderUsername` shows an action callback without href; the same
`renderNavItem` rendered it as an anchor. Login/logout and all page-navigation
items do have hrefs and remain links.

Before implementation, the new regression file failed four assertions because
profile controls were anchors rather than native buttons; the other three
interaction tests passed. Evidence: `build/eng-artifacts/T7.160/jest-red.log`.
A fresh component lint report reproduced exactly the one mapped warning:
`eslint-red.json` in that directory.

The repository uses Jest's Node environment. The tests follow its existing
Preact hook-shim pattern, invoke the actual Header component and callbacks,
and inspect real Preact vnodes. They verify:

- A profile action opens exactly one modal without calling navigation.
- Missing-user, demo and auth-disabled actions cannot activate, even when the
  callback is directly invoked; native disabled semantics are asserted.
- Mobile profile activation opens once and closes the menu.
- Navigation destinations, root live-view URL, demo login URL, translated
  labels, layout classes and mobile-link menu closure are preserved.

An explicitly invoked Chromium supplement creates native controls using the
actual Header vnode tag/type, then bridges browser clicks to the actual Header
callback. Enter and Space each activate exactly once; URL stays unchanged;
a disabled button is skipped by Tab and cannot activate with Enter/Space.
This is a native keyboard-semantics supplement, not a claim to mount the whole
application or perform a screen-reader audit. No app server or backend runtime
lease was needed. Playwright comes from the already-installed root workspace;
default Jest does not import it or gain a browser dependency.

The first optional browser run passed its assertions but exposed a fixture
cleanup error: Header's real interval outlived the mocked window. The fixture
now loads the Header with fake timers, clears them, then starts Chromium with
real timers. The corrected command exits0; the failed log remains available.
