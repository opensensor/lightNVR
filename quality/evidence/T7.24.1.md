## Behavioral oracle

Seven cases encode distinct signed PCM in mono, stereo and eight-channel layouts. Each 16-bit stream is compared call-by-call, including complete flush output, against an independent encoder receiving exactly equivalent 32-bit samples multiplied by 256. A 16-bit reversed-channel map is compared against an identity-map reference with explicitly reordered input, so both sides cannot pass by sharing the same incorrect map. Caller map storage is overwritten after open to verify the documented copy lifetime.

Input calls cover one channel group, a partial frame, an accumulated frame boundary and complete frames. Every buffer's declared final sample abuts the allocation's ASan suffix redzone. Two cases deliberately offset input by two bytes, satisfying `int16_t` alignment while failing `int32_t` alignment. Input contents and the prefix are checked unchanged. The tests compare actual nonempty encoded output, not merely status codes or configuration metadata.

Three additional cases cover invalid/short channel maps, argument rejection and empty-session draining. Negative/out-of-range map entries produce exact invalid-argument status and no handle. NULL/positive input, an over-limit whole-channel-group count, a one-byte output buffer, NULL output and NULL byte-count pointer are rejected. Output memory remains unchanged on rejection; a valid retry produces the same complete stream as a fresh reference encoder, proving rejected requests did not consume input. NULL/zero flush is bounded to 16 calls and checked against output capacity. All owned buffers and encoder handles are cleaned up even when an assertion fails; explicit successful closes null their handles.

## First observation and oracle correction

Tests were written and executed against unchanged production first. Initial artifact:

`build/eng-artifacts/T7.24.1/native-496cb9657108/`

All nine layout/map/alignment/rejection cases and the two existing controls passed. The tenth new test initially required the *first* empty-session flush to produce zero bytes; the library returned 11 priming bytes. The pinned API instead directs callers to keep flushing until zero. That first-call-zero expectation was unsupported, so the fixture was corrected to bounded draining with capacity checks. This is a test-oracle correction, **not a product RED/GREEN fix**, and the original failing `LastTest.log` is retained. No demonstrated product failure was weakened or discarded.

The public contract specifies 16-bit storage, total sample counts in whole channel groups, map copying and repeated flush calls. [Pinned upstream API documentation](https://raw.githubusercontent.com/FreewareAdvancedAudio/faac/eb4928a76fd075f9bab20e8195df84f937da289b/docs/libfaac.md).

## Limits and parent status

These cases establish observed sample interpretation, channel ordering, bounded memory accesses and argument ownership for the exercised pinned host build. The final `src += numChannels` can still form a pointer beyond one-past the input for nonzero channel indices, even though it is not subsequently dereferenced. The historical `int32_t *` intermediate also warrants language-level alignment review. Passing ASan/UBSan and successful deliberately two-byte-aligned calls do not prove those pointer constructions are valid C or portable across physical targets.
