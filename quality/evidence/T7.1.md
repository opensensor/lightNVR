# T7.1: Explicit approval for findings exceptions

The resumed T6 implementation accepted gaps whose status was `proposed-by-T6`,
and treated proposed inventory exception expiry dates as consent. The checker
now fails closed until a review is recorded. No production approval was added.

Both coverage gaps and exception dispositions require a nonempty owner and
reason, plus `approval` containing `status: approved`, `approved_by`,
`approved_on` (a valid date no later than the evaluation date), and `evidence`
(a review reference). A conflicting top-level proposed status also fails.
Missing approval is a configuration failure, so `--update-baseline --reason`
cannot turn it into acceptance. This validates the recorded review metadata;
repository review controls remain responsible for authenticating the reviewer.
