# T31: Stream-state resource disposal boundary

Static review selected an evidenced lifecycle defect rather than changing a
sound parser: `create_stream_state` initializes `mutex` and `state_mutex`, but
global shutdown destroys only `mutex` before freeing. Normal removal destroys
both. A shared private final-disposal helper can make both paths consistent.

The planned change touches one C implementation file. New focused tests use
linker wrapping of pthread mutex destruction to observe the actual lifecycle,
including refusal with extra refs, normal removal, global shutdown, repeated
shutdown and repeated cycles. No runtime network/source is needed. Tests must
first fail on the missing state_mutex destruction, then pass after the helper.

The invariant record is `quality/c-boundary.json`. The main cleanup path calls
stream manager and adapter shutdown before state-manager shutdown. This bounded
change preserves those ordering assumptions; it does not claim to solve all
existing borrowed-pointer or cross-thread lifetime questions. Final disposal
runs under the registry mutex with both per-state mutexes unlocked/quiescent.
No new allocation, callback, lock order, public API or persisted state is added.

No T7 source writer owns src/video/stream_state.c, and the new test/fragment is
unique. T13 produces the registration/runner seam. T31.1 creates precondition
regressions; T31.2 changes disposal only; T31.3 runs native and sanitizer checks.
All are explicit T32 dependencies. T27–T29 continue to gate final C integration.

`reason_not_testable`: this task selects/documents the boundary and executable
children, without production changes. Verification: source/caller review, JSON
parse, complete DAG acyclicity, ownership comparison against remediation-map.
Physical resource acceptance remains deferred by the user.
