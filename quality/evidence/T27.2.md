# T27.2 — reset the media session at a storage-pressure pause

**Complete:** four tests first reproduced retained stale state; the fix passes
84 native cases and both unchanged actual RTSP recovery scenarios. Together
with T27.1's path reservation, this closes the T27 producer's real media failures.

## Change

On entering emergency storage pressure, the managed reader now closes its old
FFmpeg input, frees its carried boundary packet, resets its stream-local audio
transcoder and segment timestamp/frame-rate state, and requests video-parameter
redetection. It preserves the stream name used for telemetry. This happens
before the first pressure sleep. A local marker makes it one reset per
continuous pause, including pauses spanning multiple 30-second wait blocks.
Recovery clears that marker and opens a fresh source session. Retry state starts
fresh; pressure policy, wait/shutdown checks, normal segment overlap, ordinary
connection reuse and forced-reconnect behavior remain unchanged.

This prevents buffered pre-pause media from being drained immediately after
source restart and stamped with current wall-clock metadata. T27.1 already
prevented that interrupted tail from overwriting another recording; this change
removes the stale-session cause of its zero-length database time interval.

## Tests first

The new `test_mp4_pressure_reconnect` executes the production reader loop with
real allocated AVFormatContext/AVPacket objects and real G.711-to-AAC transcoder
state. Only segment I/O, pressure values, pacing and reservation boundaries are
controlled seams. Another camera's flushed transcoder is retained as an
isolation control.

All **four cases failed before implementation** because the old input or pending
packet was still present at the first pressure sleep. Raw output is retained in
`build/eng-artifacts/T27.2/red-run.log`. No sanitizer diagnostic appeared during
the RED phase; the fixtures clean up resources after failed assertions.

The final cases require:

- input and pending packet disposal before sleeping, followed by successful new
  AAC output while the other camera's state remains unchanged;
- exactly one cleanup through 35 simulated pressure ticks spanning two wait blocks;
- shutdown during pause without another source/segment opening;
- audio/pending-state cleanup even when the input context is already absent.

No separate test-writer slot was available. Tests were written and run before
the production branch changed.
