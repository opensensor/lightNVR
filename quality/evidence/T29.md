## Preserved production failures

**F-T29-01: nonempty truncated media is falsely finalized.** A40-byte prefix of a
valid synthetic MP4 is unplayable, but startup sets `is_complete=1,size_bytes=40`.
`storage_reconcile_incomplete_recordings` treats any nonempty regular file as
surviving footage without checking its container/media. The lifecycle assertion
requires this fragment not be advertised as complete; it remains RED.

**F-T29-02: stale zero/missing metadata cannot be pruned.** Two rows older than
two hours remain incomplete after startup. The zero-byte file is unlinked but
its database row remains. Reconciliation calls `delete_recording_metadata`,
which delegates to `storage_recording_delete`; that operation correctly rejects
all incomplete rows inside its transaction to protect active writers. Startup
reconciliation has no distinct safe stale-orphan path. Weakening the general
active-writer guard would be an incorrect fix.

The combined stale-reconciliation check verifies valid media first, then fails
on the two retained phantom rows. No skipped test or ignored failure is counted
as a pass. Source inspection also shows that retaining bad rows in the existing
500-row repeated query needs progress/pagination care to avoid a stuck loop.
