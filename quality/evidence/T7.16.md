# T7.16 — AAC bitrate multiplication width (CODEQL-329)

The raw T1 `github/codeql-8927bc8a.sarif` finding at line 1249 has rule
`cpp/integer-multiplication-cast-to-long` and primary-location fingerprint
`3e119948d005a888:1`. The same expression remains in current source:
`faac_cfg.bit_rate_per_channel * nb_ch`, assigned to `AVCodecParameters.bit_rate`
(`int64_t`). The configuration operand is `uint32_t`; the channel count is `int`.
On this platform the multiply therefore occurs in unsigned 32-bit arithmetic
before conversion. At 64,000 bps/channel, 67,109 channels produces 4,294,976,000,
which previously wrapped to 8,704.

This is a defensive arithmetic correction, not a demonstrated reachable
large-channel exploit. `transcode_pcm_to_aac()` first opens the PCM decoder and
then FAAC. Current bundled FAAC's `validate_params()` rejects unsupported
channel counts through `GetChannelConfig()` (1–6 or 8 only), before this metadata
assignment. Maximum supported metadata is 512,000 bps at eight channels. The
local factory selects only 32,000 or 64,000 bps/channel. The positive signed
channel maximum times either bitrate fits `int64_t`; no division or allocation
uses this product. Existing negative/zero decoder-channel fallback remains mono.

Callers are the segment recorder's PCM audio setup, writer audio initialization
and `add_audio_stream()`, plus unified detection's eager pending AAC parameters.
They supply input-stream codec parameters and time bases; failures disable audio
or return an error and the probe frees its output parameters. Valid output rate,
profile, frame size, encoder delay, channel layout and ASC are unchanged.

Tests call the actual `transcode_pcm_to_aac()` implementation. Explicit linker
seams inject unsupported decoder channel counts after a real PCM decoder open
and substitute a fixed, allocation-free encoder only for arithmetic boundary
cases. These cases do **not** establish production acceptance of huge counts.
Separate controls use the real decoder and real FAAC for mono, stereo, maximum
supported eight channels, and invalid zero/negative/unsupported/huge channel
counts and zero/negative sample rates. Teardown frees parameters even after an
assertion failure. No large media buffers are allocated for boundary tests.

The production change casts the bitrate operand to `int64_t` **before**
multiplication. It neither changes supported codecs/channels nor adds an
unnecessary channel policy to the metadata calculation.

The coordinator explicitly assigned direct tests-first work because all agent
slots were occupied; a separate test-writer agent was unavailable. Tests were
written before the production edit. Native/source ownership was obtained from
the T29 worker before registration, compilation or production mutation.
