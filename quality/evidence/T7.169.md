in the six owned components. The implementation adds only explicit names to
existing inputs and textareas. It reuses localized visible labels, event/health
catalog values and tag labels. Existing nested labels, input types, IDs, form
constraints, disabled states, callbacks, selectors and dismissal policies remain
unchanged. No translation, dependency, suppression, baseline or exception changed.

health/event names use the same visible domain text. Collection rule inputs use
the existing Vendor/Model rule labels; the JSON textarea uses the existing
Advanced JSON label. Checkbox names exclude unrelated help text and changing
facet counts. Password controls keep their existing nested label and new explicit
name; clearing a configured credential still disables the password input.

## Tests first and behavior

The direct producer wrote tests before production edits because no independent
writer slot was available. `red-node.log` records missing explicit control names.
The first browser run had a nonexistent events.html fixture path; the fixture
was corrected to load the actual settings/streams CSS. The corrected pre-change
run `red-all-fixture-corrected.log` records 12 Node name failures and browser
name failures. It also exposed fixture timing and selected-camera name changes;
`red-existing-controls.log` then passes both existing bulk and camera behavior
controls before implementation. These controls were retained.

The final suite has **12 Node and seven real Chromium cases**. It renders actual
Preact components with current built CSS. HTTP services, toast delivery and the
unrelated static-members query hook use deterministic fixtures; no live backend
acceptance is claimed. The existing routing, selector and bulk payload functions
remain real implementations.

Assertions cover every reported source control, including conditional mutual TLS,
configured-password clearing, health/detection branches, all schedule days/times,
all selector value branches, camera search and advanced JSON. Node assertions
retain exact callbacks, per-rule updates, required/disabled and invalid-preview
controls. Chromium verifies computed names and native Enter/Space interaction:

- Destination names survive title removal; edits and credential clearing produce
  the exact broker/authentication/TLS payload once. Cancel and the settled Escape
  listener retain the pending-save guard and subsequent dismissal.
- Route names cover all branch controls. Mixed health/detection predicates remain
  invalid; separate valid detection and health previews preserve selected types,
  conditions, severities, days, times and suppression values.
- Bulk radio/tag selection produces one exact tag assignment. Pending controls
  remain disabled, settled Escape and backdrop dismissal remain guarded, and
  completion refreshes/closes exactly once.
- Collection creation retains required fields, trims its submitted strings,
  preserves shared visibility and writes static membership exactly once; Cancel
  and Back remain disabled during the save.
- Selector vendor/model and health changes survive mode switching. Invalid JSON
  disables preview; valid JSON produces the exact selector preview request.
- Camera search selects one camera, emits one update and disables the selected
  result. Fleet health/recording/tag toggles each emit the correct update once;
  changing counts are excluded from the control names.

Fixture corrections after initial GREEN did not alter product behavior. The route
fixture initially combined mutually exclusive predicates; it now asserts the
existing invalid guard before exercising two valid preview payloads. A combined
run exposed a race between immediate Escape injection and Preact's post-paint
listener update. The fixture now observes actual keydown listener installation
before testing pending/completed Escape behavior; it does not replace listeners
or claim synchronous effect installation. No modal lifecycle policy was changed.
