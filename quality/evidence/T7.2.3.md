## Deterministic descriptor failure

`_chmod_path()` returns success for ELOOP before writing `fd_out`.
`chmod_recursive()` then consumes its uninitialized `int fd`. The coordinator
approved compiling the **unchanged** path_utils.c as a separate test-only object
with `-ftrivial-auto-var-init=zero` (compiler capability checked). Production
lightnvr_lib flags/source properties are untouched. This deterministically
selects one possible uninitialized value; it is not a claim that every ordinary
production build selects zero, nor a sanitizer discovery.

The public recursive API runs in a forked child whose fd0 is deliberately
replaced with a disposable sentinel file. Current code passes that unowned fd to
fdopendir, then closes it on failure. The child exits21 (sentinel descriptor
closed) instead of0. The parent descriptors are unaffected; child is waited for.
The proposed exact fix is to initialize `*fd_out=-1` before every early return,
while retaining normal directory-fd ownership. T7.2.8 was materialized by the
coordinator before production editing.
