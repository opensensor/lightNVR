## Invariants and bounded change

`authorization_context_t` is opaque outside this file. Its constructor uses
`calloc`; each request owns and frees its context, and its header prohibits
cross-thread/request sharing. Cache counts start at zero, increase only after
successful growth, and capacity starts at zero then grows 4, 8, 16, etc. A failed
`realloc` leaves both the original pointer and capacity intact. Grant loading's
database count is a separate field inside each cache entry, not the cache's own
index. There is no public setter for either cache count.

Callers in fleet, streams, investigation and camera filtering reuse a context
for user/action/resource evaluations. Grant entries memoize a user/action pair;
collection entries memoize collection UUIDs. The public API does not impose an
arbitrary new per-context ceiling, and this change does not introduce one.

Previously `grow_array()` evaluated signed `capacity * 2` without a
representability guard, then multiplied the converted capacity by item width
without checking size_t overflow. At capacity 1,073,741,824, UBSan reports signed
overflow on this host. The test seam's width `SIZE_MAX / 8 + 1` and initial
capacity 4 wrap the byte count to zero; the allocator may then return a nonnull
zero-byte allocation and the helper commits capacity 8. The seam intercepts
large allocations, so neither test reserves huge memory or fabricates a huge
backing array. The artificial width is not a production entry size, and the
huge-capacity test does not establish a feasible request allocating that many
entries. The existing public-input negative-index warning remains unconfirmed.

The helper now rejects negative capacity and capacity above `INT_MAX / 2` before
doubling, then checks the resulting count against `SIZE_MAX / item_size` before
the multiplication (preserving existing zero-width semantics). Normal callers
use nonzero structure widths. Capacity changes only after allocation succeeds.
Thus growth from a valid nonnegative state cannot introduce an overflowing
capacity; no cast-only workaround or scanner suppression is used.
