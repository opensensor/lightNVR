# T7.164 — user-dialog click boundaries

All ten mapped click-events-have-key-events occurrences are resolved in the six
owned user components. These surfaces are modal/backdrop boundaries, not extra
activation controls. Native Close/Cancel and action buttons remain responsible
for keyboard activation; existing dialog keyboard handlers remain unchanged.
No translations, dependencies, suppressions, findings-baseline edits or policy
exceptions were added. Caller tracing confirms UsersView.closeModal only clears
activeModal; Header.closeProfileModal only clears its open state. Neither depends
on the click event argument. EditUser remains the shared profile editor as well
as the user editor.

- AccessPolicy, ApiKey and AuditHistory: the outer backdrop has presentation
  semantics and dismisses only when target equals currentTarget, subject to the
  exact existing saving/creating/reveal/export guards. Click containment moves
  from the inner dialog to that outer boundary; inner stop-click handlers are
  removed. Existing dialog roles, global Escape handlers, confirmation dialogs,
  disabled buttons and service callbacks remain unchanged.
- DeleteUser: the same target-only presentation boundary replaces the outer
  unconditional dismissal and inner stop-click pair. The existing delete handler
  and AsyncButton pending protection remain. Native Cancel still supplies
  keyboard dismissal. This task does not claim broader dialog semantics, Escape
  dismissal, focus trapping or focus restoration for this older component.
- AddUser/EditUser: only role=presentation is added to the outer backdrop. Their
  existing mouse-down-origin latch, target check, inner click containment,
  Escape handling, focus traps and initial focus behavior remain verbatim.
  EditUser's existing focus restoration is preserved. No synthetic Enter/Space
  handling or blanket key suppression was added.

## Tests first and browser controls

There was no independent test-writer slot, so this task used direct tests-first
work. `web/tests/remediation/t7_164.spec.jsx` was written before production edits.
The initial Node run failed ten assertions (six presentation-boundary contracts
and four target-only boundary contracts), while 22 existing behavior controls
passed; three browser cases were initially unselected (`jest-red.log`). These
boundary assertions do not claim the old inner stop-click handlers allowed
ordinary content clicks to dismiss the modal; they require the replacement
boundary itself to distinguish target from bubbled content.

The final default suite passes 32 Node tests, with four browser supplements
unselected. Those supplements were explicitly run and pass all 36 tests:

- Add/Edit/Delete native Enter and Space dismissal, real pointer backdrop
  dismissal, visible focus styling from built Users CSS, one action dispatch,
  disabled pending actions, no repeat activation while pending and subsequent
  pointer activation. Add/Edit also retain both Tab-wrap directions, inside-to-
  outside pointer drag protection, field Space behavior and Escape dismissal;
  Edit retains return focus to its launcher.
- Access/API nested confirmation Escape dismisses the child only. Enter/Space
  activation retains one pending save/generation request; parent Escape and
  backdrop dismissal stay blocked while the original guards apply. API secret
  reveal still blocks dismissal until its saved-confirmation checkbox enables
  native Done. The tests use the actual ConfirmDialog and AsyncButton code.
- Audit tests exercise real retention-save and export pending states: Close is
  disabled, Escape/backdrop cannot dismiss, and normal Escape returns afterward.
  A separate fresh-mount saving test excludes prior modal history as a variable.
- All browser cases assert zero uncaught page errors. They mount real Preact,
  use actual Users CSS and mock only external services/i18n. No backend server,
  actual user mutation or live API is used; export contains a synthetic Blob.

Fixture debugging logs are retained rather than presented as product failures.
Initial browser fixtures incorrectly selected AsyncButton by its idle name while
its pending spinner replaced that name, pressed confirmation Escape before its
focus effect settled, and assumed API Done returned to the token list (it
correctly closes). Those expectations were corrected to existing source behavior.
The Audit fixture also used `timestamp` instead of the API's `occurred_at` field;
EventCard then threw `Invalid time value` during rendering and prevented effect
updates. The apparent stale Escape guard therefore reproduced even in a single
mount. Explicit page-error capture (`audit-page-errors.log`) exposed the malformed
fixture. Correcting the field made the retained saving/export and isolated Escape
assertions pass without changing any product guard. Settings fixtures include
allowed_decision_modes. Earlier browser-red*, audit-isolation and audit-complete-
fixture logs document the investigation; final browser-green and combined-green
logs contain the successful runs.
