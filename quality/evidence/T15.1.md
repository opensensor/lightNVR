# T15.1 — Existing test command and workflow compatibility

## Changes

Root npm test/API/UI/go2rtc commands now enter the owned runner. `npm test`
preserves all projects, API/UI retain their tag filters, and go2rtc selects the
seven actual tagged tests in the API project (the separately named legacy
project matches no files). No package dependencies or lockfiles changed.

The wrapper accepts validated all-project, grep, exact-file and shard selection,
including `--flag=value` syntax. Exact files must resolve under tests/integration;
regex metacharacters in their paths are escaped. Dangerous arbitrary configs,
unsupported options, malformed shards and outside paths fail. `--list` performs
only discovery: no native build, binary access, runtime lock or server directory.

The named `health` profile preserves MQTT enabled with the original health
settings, go2rtc disabled, and the deliberately unreachable loopback broker at
18884. Execution requires an explicit MQTT-enabled binary; it never substitutes
the default MQTT-disabled build. Both IPv4 and IPv6 broker ports must be free.
The separate real-broker presence gate is unchanged.

The existing health workflow still selects its same four files with its
MQTT-enabled prebuilt binary. Existing UI matrix shards remain 1/2 and 2/2 with
their prebuilt server. Python is explicitly installed in the UI job for pidfd
cleanup. Workflow-wide process-name kills and shared /tmp deletion are removed.
The runner already cleans verified owned processes; failed cleanup stays failed.

Runtime execution produces list, JSON and HTML reports with HTML auto-open
suppressed. Allowlisted regular owned configuration/log files are copied into
per-run artifacts even after failure. Symlinks and unrelated files are not
copied. CI uploads that task's artifact tree; it no longer collects a broad /tmp
path. Legacy explicit-path screenshots remain separately uploaded from the
job-local test-results directory.

[docs/TESTING.md](../../docs/TESTING.md) documents discovery, exact filters,
profiles, prebuilt binaries, reports and cleanup. Root test:report still accepts
an explicit report path; the guide uses the printed per-run HTML location.

## RED → GREEN

Five new tests initially failed on absent parser/archival exports or missing
server-free discovery (`build/eng-artifacts/T15.1/red.log`). Final
`python3 -m unittest discover -s tests/quality -p test_runners.py` passes **22/22**.
The new cases exercise real argument selection, near-match path rejection,
malformed/unsafe options, preservation of health MQTT config, discovery with a
nonexistent binary and unchanged temporary runtime inventory, and rejection of
external symlinks/unrelated data during log archival. The initial escaped-string
assertion in the test itself was corrected to assert regex matching semantics,
including rejection of a near-match filename; no product criterion was weakened.

Root `npm run typecheck:tests` passes. YAML parses with the installed `yaml`
package; all four original jobs remain. The only job changes are the existing
health/UI invocation/artifact steps, removal of unsafe cleanup, and Python as a
UI cleanup prerequisite. No scanner policy, exception, repository rule or remote
setting changed.
