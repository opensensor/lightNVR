# Migration from Snowpack to Vite

This document outlines the migration from Snowpack to Vite for the LightNVR web interface.

## Why Migrate?

Snowpack is no longer maintained, while Vite is actively developed and offers better performance, features, and community support.

## Changes Made

1. **Configuration Files**:
   - Created `vite.config.js` to replace `snowpack.config.js`
   - Updated `postcss.config.js` to use ES modules syntax
   - Updated `tailwind.config.js` to use ES modules syntax

2. **Package.json**:
   - Updated scripts to use Vite instead of Snowpack:
     - `start` now runs `vite` instead of `snowpack dev`
     - `build` now runs `vite build` instead of `snowpack build`
     - Added `preview` script to run `vite preview`
   - Added Vite and related dependencies

3. **Build Scripts**:
   - Created `build_web_vite.sh` to replace `build_web_snowpack.sh`
   - Created `build_and_update_web_vite.sh` to replace `build_and_update_web_snowpack.sh`

## How to Use

### Development

To start the development server:

```bash
cd web
npm run start
```

This will start a development server at http://localhost:8080.

### Production Build

To build for production:

```bash
cd web
npm run build
```

Or use the build script:

```bash
./scripts/build_web_vite.sh
```

This will create a production build in the `web/dist` directory.

### Preview Production Build

To preview the production build:

```bash
cd web
npm run preview
```

## TypeScript

Vite compiles `.ts` and `.tsx` with Oxc using the same Preact JSX settings as
`.jsx`, and only strips types. `npm run typecheck` is what checks them, and CI
runs it in `static-analysis.yml`.

- `tsconfig.base.json` holds the shared strict options. Do not relax them.
- `tsconfig.json` covers `js/**`; Vite's client types come from `js/env.d.ts`.
- `tsconfig.tests.json` covers TS tests under `tests/` with Jest and Node types.
- `allowJs` is on and `checkJs` is off, so TS can read the two `.js` exceptions
  below without checking them. `// @ts-nocheck` is a lint error and fails
  `tests/typeEscapes.spec.js`.
- Jest compiles `.ts`, `.tsx`, and `.jsx` through the overrides in
  `babel.config.cjs`. Plain `.js` compiles as before.
- ESLint parses `.ts` and `.tsx` with the TypeScript parser and keeps the a11y and
  i18n rules on them. `no-explicit-any` and `ban-ts-comment` are errors;
  `@ts-expect-error` needs a reason on the same line. `tests/typeEscapes.spec.js`
  also fails on `@ts-nocheck`, `@ts-ignore`, or any `any` type in `js/`.
- `i18n-literal-baseline.json` keeps its `.jsx` keys: the rule reads `X.tsx` as
  `X.jsx`, so counts carry across a rename.
- `tests/types/tsxFixture.spec.tsx` runs TSX through Preact in Jest. Its
  `@ts-expect-error` is a permanent check that prop types are enforced, so
  removing that line must make `npm run typecheck` fail.

## TypeScript conventions

All first-party `js/` source is strict TS/TSX, apart from two exceptions:

- `js/utils/theme-init.js` stays `.js` because `vite-plugin-theme-inject.js` reads
  it by that path at build time, regex-matches `export const COLOR_THEMES = {...}`,
  and evaluates the text with `new Function`. A rename or a type annotation breaks
  HTML injection. This is the file that needs `allowJs`: without it,
  `ThemeCustomizer.tsx` gets TS7016 and an implicit `any`.
- `js/version.js` is generated by `scripts/extract_version.*` and git-ignored.
  `js/version.d.ts` sits beside it, so typecheck also works when it is absent.

Remove `allowJs` only once neither `.js` file exists.

Typing a file must not change what it does. To prove that, compare esbuild's
type-stripped output with the previous revision:
`transformSync(src, { loader: 'tsx', jsx: 'preserve', target: 'es2022', legalComments: 'none', tsconfigRaw: { compilerOptions: { verbatimModuleSyntax: true, jsx: 'preserve' } } })`.
esbuild keeps comments inside object literals and before JSX, so put new comments
above the statement.

**Escape hatches.** No `any`, `@ts-ignore`, or `@ts-nocheck`. `@ts-expect-error`
needs a same-line reason, and is for a real bug being left in place or a type that
cannot describe the code. `as unknown as` needs a comment. Use non-null `!` only
where the invariant is locally obvious.

**Types**

- Shared shapes live in `js/types/` (`core.ts` plus one file per domain). Helper
  and prop types are exported beside their code.
- `import type` for types. Babel's `onlyRemoveTypeImports` keeps any plain import.
- Types describe what the code does now, read from the C handlers in `src/web/`.
  Mark unverified API fields optional. Fields the code reads but no handler emits
  stay on a local extension type with a comment.
- Annotate first, then read the errors: `useState<T>`, `useRef<T | null>(null)`,
  one props interface per component, and `useMutation<TData, TError, TVariables>`
  clear most of them.
- `fetchJSON<T>` and `useQuery<T>` default to `unknown`. Annotate
  `const data: Foo = await response.json()` so `any` does not flow on.
- `declare` class fields assigned in a constructor. A plain field declaration
  emits a class field and changes output.
- Window globals go in the owning file with `declare global`.

**Preact**

- Use Preact's types from `preact`, not React's. `e.target` is
  `EventTarget | null`, so keep existing reads as
  `(e.target as HTMLInputElement).value` rather than switching to `currentTarget`.
- Preact types `maxLength`, `rows`, `colSpan`, `tabIndex`, and `aria-value*` as
  numbers: write `rows={4}`, not `rows="4"`. The DOM result is the same.
- Write `spellcheck={false}`, in lowercase. `spellCheck={false}` silently does
  nothing: `spellCheck` is not a DOM property, so Preact falls back to attributes,
  and a `false` attribute value is removed. The field stays spellchecked.
  (`spellCheck="false"` happens to work, but its type is rejected.)
- `const x = a && b && c` used as `disabled` may include `null`, which Preact's
  types reject. `disabled={x as boolean}` compiles but is a cast, not a check.

**Traps**

- `Array.isArray` narrows a `readonly T[]` union to `any[]` with no error, which
  silently removes checking from the rest of the function. Keep such parameters
  mutable (`T[] | null | undefined`).
- `Number.isFinite` takes `unknown` and does not narrow; cast at the use.
- `filter(Boolean)` does not narrow; cast the result.
- `let x = null as T | null` stops flow narrowing when a closure assigns `x`.
- `parseInt(x as string, 10)` keeps output; `String(x)` changes it.
- Index a literal map with a wider key using
  `({...} as Partial<Record<string, V>>)[key]`. The parentheses are erased.
- `useQuery`'s `placeholderData: (prev) => prev` and a mutation's `.isPending`
  compile, but both are v5 forms that do nothing on query-core 4.x.

## Directory Structure

Vite uses a slightly different output structure than Snowpack:

- JavaScript, CSS, and other assets are placed in the `dist/assets` directory
- HTML files are placed in the `dist` directory

## Notes

- The migration maintains the same functionality as the Snowpack build
- Vite provides better performance and more features
- The build process is faster with Vite
