# Bounded host soak composition

Run `python3 scripts/quality/soak.py --profile ci --output build/eng-artifacts/T30` after reserving the shared native/server/media lease. The default binary is the existing integration build; supply `--binary /absolute/path/to/lightnvr` to select another immutable executable. The tool does not build or modify fixtures, scenario tolerances, runtime budgets, application state, or existing services.

`ci` runs the existing T27 video-only, T27 H.264/AAC pressure/reconnect, and T29 upgrade/record/restart/crash scenarios twice each. Each child acquires/releases its existing runtime lock; the supervisor does not acquire a nested lock. The 300-second child ceiling contains hangs and is not a physical recovery budget. Existing scenario assertions/deadlines remain unchanged. A leftover lock stops composition and is preserved for investigation. Cleanup pins observed descendants with Linux pidfds; no numeric-PID/name-based kill fallback exists. A forced cleanup is a failure.

Exit codes are 0 for qualified, 1 for functional failure, and 2 for functional success with incomplete qualification. Every missing/null runtime limit is reported dynamically from `quality/runtime-budgets.json`, never coerced into an unlimited/passing limit. Growth thresholds also remain null. Synthetic numeric limits in unit tests prove failure propagation only.

The output has a unique directory containing exact source/binary/configuration/tool provenance, per-run raw samples, copied scenario artifacts, runner logs, supervisor results, and summary.json. Working-tree status and source hashes disclose concurrent documentation/test changes; the binary hash is checked before every run. The baseline/candidate physical comparison protocol in T5 is not executed by this short host profile.

Only descendants of the actual spawned runner are observed. Each `/proc` read is checked against PID/start/executable/argv identity before and after measurement. Every ancestry edge is revalidated against current identities, and the full chain is checked before and after pidfd pinning; stale parent-PID reuse cannot authorize cleanup. NVR and managed child RSS/CPU/FD/thread totals are separated from synthetic-source and browser branches. In T29, its go2rtc is managed but the synthetic lavfi FFmpeg branch is a source; in T27, the standalone go2rtc source and descendants are sources. Source generation remains on this host, not on a separately qualified target. Unknown helper processes are reported individually and excluded from NVR totals.

CPU uses delta process ticks / CLK_TCK / monotonic elapsed time ×100, where one core is 100%; a first observation has no delta and is null. RSS is a sum and can double-count shared pages. Growth is the maximum increase from the first sample within each NVR PID/start-time lifetime; restart cannot hide an earlier window's growth. Missing values inside a lifetime invalidate its comparison instead of being filtered out. Mixed startup/recording/shutdown phases remain an informational conservative growth check, not a stable-phase leak proof. Proven normal exits close windows and retain exit events with metrics unavailable at that instant; they do not by themselves invalidate otherwise complete samples. Reused/unreadable/unverified ownership remains incomplete, never zero. Idle versus recording RSS phases and browser startup/heap/long-task metrics are unavailable; browser process resource samples are not substitutes for them.

Recovery and recording-gap values come from unchanged T27 reports: gap checks compare adjacent committed DB segments within the before/after sequences, excluding the intentional outage; packet/decode assertions remain in T27. T29 preserves its 13 functional assertions and normal shutdown deadlines. A false child exit, missing report, incomplete assertion set, sanitizer log, forced cleanup, missed recovery deadline or unexpected gap prevents functional success.

## Standalone ThreadSanitizer assessment

This task does not execute or qualify TSan. Current CMake Debug mode unconditionally adds `-fsanitize=address,undefined` for supported compilers. The existing native runner accepts `none` and `asan-ubsan`; it has no TSan mode. Reusing either a Debug directory or an ASan artifact for TSan would be invalid.

A future bounded TSan task should use a fresh build directory with a non-Debug build type, explicit compile/link `-fsanitize=thread -g -O1 -fno-omit-frame-pointer`, and verified absence of ASan/UBSan flags in every tested target. Start with a minimal pthread race control that must report its deliberate race, then a no-race control, then selected coordinator/state/storage concurrency tests. Archive compiler/runtime, full commands and loaded dependency identities. Do not treat successful compilation as working runtime support.

The current host/toolchain's TSan runtime startup, memory-mapping compatibility, and third-party FFmpeg/SQLite/libuv/TLS instrumentation have not been tested. Uninstrumented dependencies limit race visibility even if application tests run; suppression or disabling tests cannot silently turn those gaps into a passing qualification. Go go2rtc requires its own race-instrumented toolchain/binary and is not covered by C TSan. A separate plan task and exclusive native lease are required before this proposed experiment; no shared build configuration was changed here.
