# Plan: Host and Hardware Health Observability

**Generated**: 2026-09-03
**Mode**: Swarm-ready dependency plan

## Overview

Implement `docs/prd/OPS_03_Host_Hardware_Health.md` as a bounded Linux health
subsystem whose immutable snapshot is the single source of truth for policy
evaluation, the System API/UI, and Prometheus. Portable `/proc`, cgroup,
filesystem, network, thermal, clock, and restart evidence lands with the
incident state machine first. Normalized event transitions, MQTT presence,
optional hardware providers, and operator UI build on that boundary without
moving probes into recording, web-request, or MQTT-delivery threads.

The work is divided by translation unit and API boundary. `T1` creates source
and test-registration seams so later workers can add collector-specific files
without editing shared CMake lists. Database migrations are serialized through
`T7`, `T8`, and `T16`. High-conflict lifecycle, generated migration, and final
integration work stays local or is strictly dependency ordered.

Milestone A (`T1`-`T12`, `T19`, `T20`) is the P0/P1 portable release. P2 and P4
can proceed independently from the additive P3 hardware-provider branch after
that milestone; P3 must not hold up portable health coverage.

## Assumptions

- This plan implements PRD phases P0-P4. P5's separate least-privilege host
  service/protocol remains deferred until a concrete Docker or Home Assistant
  deployment requires it.
- Portable sampling is enabled by default with the balanced profile. The PRD's
  numeric hardware-sensitive defaults remain provisional until `T25` records
  the required replay and device-matrix evidence.
- Dynamic producer-selected event severity is accepted. The registry supplies
  a default plus an allowed severity range, so existing producers remain
  source-compatible while health incidents can escalate without contradictory
  envelope and payload severities.
- Existing `/api/health`, stream-health behavior, storage-pressure topics and
  events, and Home Assistant availability topics remain compatible. Operational
  health never changes liveness HTTP status or invokes the current web-server
  self-healer.
- SQLite stores incident state and transitions only; periodic raw samples remain
  bounded in memory and are exported through API/Prometheus.
- The committed migration sequence ends at `0080`. The working tree also has an
  unrelated untracked `0079_add_detection_label_lookup_index.sql`; workers must
  preserve it. `T8` tentatively reserves `0081` and `T16` `0082`, but each task
  must re-check the entire working tree immediately before creating its file and
  stop for integration if either number has become occupied.
- The checked-in `db_embedded_migrations.h` says it is generated by
  `scripts/generate_embedded_migrations.py`, but that script was removed in
  commit `473110c5`, and the current header uses a compact hand-maintained style.
  `T7` restores a deterministic, checkable update path that preserves existing
  bytes on a no-op update; workers do not hand-edit the generated header.
- All workers share a non-clean repository. They must edit only their assigned
  ownership, preserve unrelated changes, avoid commits unless requested, and
  report every path changed. An ownership collision or missing prerequisite is
  a blocker to record in the task log, not permission to overwrite another
  worker's work.
- Public labels use logical filesystem IDs, bounded interface/sensor IDs, and
  installation-scoped device hashes. Raw paths, IP addresses, serials, WWNs,
  arbitrary error strings, and vendor attribute names never enter events or
  metric labels.

## Prerequisites

- A Linux build host with the repository's normal C/CMake dependencies, Python
  3 for migration generation, Node 24 for Web UI tests, and libmosquitto plus a
  disposable Mosquitto broker for MQTT integration tests.
- Writable task-specific build directories under `build/swarm-t<N>`; parallel
  workers must not share a CMake build directory.
- Fixture snapshots for bare metal, cgroup v1, cgroup v2, old/missing-kernel
  files, malformed/overflow inputs, permission failures, counter resets, and
  disappearing sensors. Fixtures contain synthetic identifiers only.
- For `T18`, fixture output from supported smartmontools releases and review
  against the current upstream `smartctl` JSON contract. The upstream source
  advertises `-j/--json` and a versioned `json_format_version` object:
  <https://www.smartmontools.org/static/doxygen/smartctl_8cpp_source.html>.
- For the final calibration gate, access to at least one 256 MB embedded target,
  an ARM SBC, an x86 host, cgroup-limited Docker, rotating media, SSD/NVMe, and
  a slow/unavailable network mount. If that lab is unavailable, `T25` remains
  explicitly blocked and thresholds remain marked provisional.
- A test MQTT subscriber must run outside the LightNVR process so kill/LWT and
  stale-heartbeat behavior can be observed rather than inferred locally.

The executor may run at most the available worker slots from a wave at once and
queue the rest; wave membership denotes dependency safety, not a requirement to
start every task simultaneously. Because all agents see the same source tree,
each parallel wave has an edit barrier: workers first finish atomic edits and
report edit-ready, the coordinator freezes that wave's writes, and only then do
workers run their task-specific configure/build validation. If the executor
cannot enforce that barrier, it must serialize tasks or use isolated worktrees.

## Integration Strategy

- Before each wave, verify all dependencies are marked Completed and inspect
  `git status --short`. Workers operate in their explicit ownership and report
  paths; they do not revert, format, or stage unrelated user changes.
- `T1` is the only early task allowed to change shared CMake registration.
  Collector/provider workers add their own sources and one unique CMake test
  fragment. `T26` is the only later task allowed to reconcile those shared
  lists.
- Migration work is serialized: `T7` establishes tooling, `T8` adds the incident
  schema, and `T16` adds managed status topics. Each rechecks the whole working
  tree for version collisions and regenerates the header; no parallel task edits
  the generated header.
- `src/core/main.c` changes are ordered `T9` then `T10`, with final lifecycle
  reconciliation in `T26`. Health stop/join occurs before telemetry/database
  cleanup even on partial initialization and emergency paths.
- API and metrics implement generic bounded observation arrays, so later P3
  providers appear without provider-specific handler code. UI likewise renders
  registry/resource groups rather than hardcoding SMART attribute names.
- Merge/test Milestone A after `T20`: portable collection, persistence,
  evaluation, storage/write evidence, API, and metrics must be coherent before
  P2 delivery or P3 hardware is presented as supported.
- When a task is blocked, record the exact missing artifact/tool/ownership
  conflict in its log, leave it Not Completed, and continue only tasks whose
  dependencies remain satisfied. `T25` may remain blocked without preventing
  `T26`; in that case defaults and documentation stay explicitly provisional.

## Testing Strategy

- Pure parser tests use synthetic injected `/proc`, sysfs, cgroup, mount, clock,
  and smartctl fixtures, including missing, malformed, overflow, reset, wrap,
  permission, and disappearance cases.
- State-machine replays use a fake monotonic clock and restartable SQLite DB to
  prove dwell, hysteresis, escalation, persistence, one-shot, and recovery
  cardinality without sleeping.
- Storage/video tests inject syscall/FFmpeg results and a hung probe while a
  sentinel recording loop verifies the health path never blocks writer work.
- API/Prometheus tests freeze a snapshot generation and assert repeated and
  concurrent reads are side-effect free, bounded, privacy-safe, and compatible.
- MQTT tests use a real disposable broker plus an external subscriber for LWT,
  retained online/stopping, stale heartbeat, reconnect, multiple destinations,
  and broker-outage/outbox recovery.
- Web unit tests cover rendering/config mapping/permissions; Playwright covers
  System Health, history, settings, event routes, and unknown/container states.
- The benchmark enforces heap, CPU, cardinality, deadline, and shutdown budgets.
  Hardware replay/field results, not intuition, decide whether provisional
  thresholds can be frozen.

## Risks and Mitigations

- **Risk**: Health sampling harms recording on small devices or stalled network
  mounts.
  **Mitigation**: Fixed capacities, tiered workers, overlap suppression, hard
  deadlines, interruptible shutdown, atomic writer-side error reporting, and
  explicit `T24` resource/sentinel gates.
- **Risk**: Container facts are presented as host facts.
  **Mitigation**: Scope/capability is mandatory on every observation, cgroup
  precedence is tested, and API/UI show an explicit coverage banner.
- **Risk**: Diverse hardware produces false alerts.
  **Mitigation**: Prefer kernel/vendor limits, require dwell/hysteresis,
  capability-gate providers, keep defaults provisional, and block threshold
  freeze on the replay/device matrix.
- **Risk**: Parallel agents collide in CMake, lifecycle, locales, or generated
  migrations.
  **Mitigation**: Per-task CMake fragments/build dirs, dependency-ordered shared
  files, serialized migrations/UI locales, and a local final integration task.
- **Risk**: Events flap or contradict their envelope severity.
  **Mitigation**: Persist stable incident IDs, emit transitions only, constrain
  dynamic severity in the registry, and test payload/envelope equality plus
  outbox retries.
- **Risk**: MQTT cannot report its own or the host's death.
  **Mitigation**: Broker-side LWT and external stale-heartbeat tests; API and
  Prometheus expose local delivery failure; documentation requires an
  independent observer when broker and NVR share a failure domain.
- **Risk**: Hardware helpers expand privileges, leak identity, or hang.
  **Mitigation**: Optional explicit enablement, fixed argv/no shell, sanitized
  environment, capped output/concurrency/deadline, installation-scoped logical
  IDs, no default privileged container packaging, and kill/reap tests.
- **Risk**: Incident persistence fails during the disk failure it is reporting.
  **Mitigation**: Evaluator retains bounded current state in memory, records
  normalized local diagnostics, attempts non-durable presence updates, and
  makes the independent external observer limitation explicit.
